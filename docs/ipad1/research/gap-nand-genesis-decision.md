# iPad1,1 / iOS 3.2 (7B367) NAND: kernel format/restore paths vs. offline generator — findings

All kernel facts below come from disassembly of `$SP/dec/kernelcache.k48.mach` (prelinked kexts; no symbols). Kext load addresses (from `__PRELINK_INFO`): `AppleNANDFTL` text `c07ee000` (file 0x7b7000), cstrings `c080cc88`; `IOFlashStorage` text `c04dd000`; `AppleS5L8920XIOPFMI` text `c04e7000`; `EncryptedBlockStorage` text `c04d9000`; `AppleS5L8920XARM7M` text `c04d1000`; `IOP_S5L8930X_firmware` `c074a000`. Nothing was written to any repo; ramdisk files were parsed in memory (the ramdisk is HFS+ with decmpfs-compressed files — `com.apple.decmpfs` xattr types 3 (inline zlib) and 4 (resource-fork chunked zlib); that is why earlier extractions gave 0-byte files).

## 0. Executive answer

1. **The 3.2 kernel formats a blank NAND by itself** when boot-args contain `nand-enable-reformat=1` (or `nand-wipe=1`): `WMR_Start` (`c07f1a64`) → `VFL_ProductionFormat` (creates DEVICEINFOBBT special pages) → `VSVFL_Format` → `YAFTL_Format` (erases every usable block, writes **no** FTL context) → writes NANDDRIVERSIGN → `VFL_Open` → `YAFTL_Open` which, finding no `CX01`, runs "full NAND R/O restore" on the empty FTL. `restored_external` is **not** needed for the NAND format itself; it is only needed to create the MBR + HFS+ volumes (MediaKit + `newfs_hfs` + `asr`).
2. **Every approach needs a working IOP program/erase path**: the kernel writes to NAND on any rw mount (and the format/restore/epoch paths erase+program). A "read-only H2FMI" model can only boot an all-`ro` fstab demo.
3. **Recommendation: offline generator (A)** — its previously-unknown values are now determined from the kernel (§2, §3, §5, spec in §7), **plus** use the kernel's own self-format (C) inside the emulator as the *oracle* to diff against (blank image + `nand-enable-reformat=1`). Full Apple restore (B) is not needed: it adds DFU/recovery USB, restore-mode protocol, ramdisk boot and asr-over-usbmux for no information the generator does not already have.

## 1. AppleNANDFTL::start → WMR_Start: boot-args and decision logic

`AppleNANDFTL::start` (`c07f0a9c`–`c07f1290`), boot-args parsed via `PE_parse_boot_arg` (blx r11) into the `WMR_Start` flag word (r8):

| boot-arg / property | effect | where |
|---|---|---|
| `nand-enable-reformat` (value!=0) | flags bit0 = "format allowed" | `c07f1220`–`c07f0bdc` |
| DT `metadata-whitening`==1 (read from provider IOFlashStorageDevice) | bit10 (0x400), sets obj+0xb0 | `c07f0be6`–`c07f0c32` |
| DT `default-ftl-version`==1 | bits 2,3 (0xc = VSVFL+YAFTL); absent/other → 0x20 (legacy VFL/FTL, BLOCKZERO signature style) | `c07f0c36`–`c07f0c78`, `c07f123c` |
| `diag-bits` | 0x200 | `c07f0c86` |
| always | 0x100 | `c07f0cd0` |
| `nand-check-vs` | local: after init, if VS type mismatch → "marking the device for format" (`c07f0e94`) | `c07f0cc8` |
| `nand-erase` | panic "nand-erase is no longer supported" | `c07f0ce4` |
| `nand-wipe` | device-status="format", 5 s delay, flags |= 0x3 (format + *production reformat*) | `c07f0d30`–`c07f0dae` |
| `nand-enable-yaftl` | |= 0xc | `c07f0db2` |
| `burnin-size` | |= 0x10, size MB | `c07f0dc6` |
| `nand-force-restore` | |= 0x80 (passed as arg 3 of FTL_Open) | `c07f0df8` |
| `nand-whiten-metadata` (only if DT whitening) | |= 0x800 (enables the "whitening mismatch" check) | `c07f0e16` |
| `nand-neuralize` | after AND init: `andGetStruct(0x10000800)` → FPart[0x18] erases *every* block on every CE incl. block 0/special blocks, then spins | `c07f0e4e`–`c07f0e92` |
| `nand-set-rma` / `nand-reset-burnin` | VFL_SetStruct 0x02001600 | `c07f0ecc` |

`WMR_Start(pTotalPages=obj+0x160, pBytesPerPage=obj+0x164, flags, blockOffset=obj+0x17c)` (`c07f1a64`, `Whimory/Exam/WMRExam.c`). `blockOffset` = 1 when the provider is `IOFlashStorageDevice` (`c07f0b32`) — the iPad case, since `IOFlashPartitionScheme::probe` fails without `/chosen/boot-from-nand` (`c04e1424`–`c04e1434`); so the FTL area starts at physical block 1, matching openiBoot `reserved_blocks = 1`.

Flow (`c07f1aaa`–`c07f20ea`):
1. `FIL_Init`; `FIL.GetDeviceInfo(0x65)` (CS count)==0 → "[FTL:MSG] No NAND attached". `BUF_Init(0xc,0xa)` (12-byte meta, 10 valid).
2. FPart: table `c0816504` zeroed, `FPart_Register` (`c07fcf88`), `FPart_Init(blockOffset, opts=(flags>>8&1)|(flags&0x200?2:0))` (`c07fd008`) — copies device info from `FIL.GetDeviceInfo` into `c0816870` (see §1.1), allocates special-block cache (CS×0x100 B at `c08157d4`).
3. Signature style `FPart[0x38](0x65)` → "RESERVEDBLOCK HEADER": `FPart[0x30]=ReadSignature=c07fdba4`, `FPart[0x14]=WriteSignature=c07fdc3c` (legacy 0x64 → `c07fd220`/`c07fd178`, block-0 no-header) (`c07fcf34`).
4. `ReadSignature(c081628c, 0x108)` → if found: byte3=='C', byte2∈{'0','1'}, byte1∈{'0','1'}; if byte2=='1' require `(flags&0xff)<=5`; else "[FTL:WRN] Incompatible Signature!" → treated as not found (`c07f1bbe`–`c07f1c0c`). If flags bit11: sig flag 0x10000 must equal DT whitening else "[FTL:ERR] metadata whitening mismatch, please reformat" → fail (`c07f1c1a`–`c07f1c50`).
5. Not found and bit0 clear → prints "[WMR:ERR] NAND format invalid (mismatch, corrupt, read error or blank NAND device)", "AND: NAND initialisation failed due to format mismatch or uninitialised NAND.", "AND: Please reboot with reformatting enabled." → returns 0x80000001 → `AppleNANDFTL::start` "AND init failed", device-status "failed" (`c07f1c70`–`c07f1cb8`, `c07f0e48`).
6. With bit0: `boolProductionFormatVerified = FPart[0x24]()` (`c07fe19c`: DEVICEINFOBBT readable on **every** CS, trying data-whitening on then off); `FIL[0x40](1)` (Notify: device-status "format").
7. VSVFL registered (`c07f927c` fills `c081649c`); `nSig = c04e0f79() | 0x43313100` where `c04e0f79` returns `'0'+PE_nand_epoch()` and `c01d1100` returns constant **1** → `nSig = 0x43313131` (bytes `31 31 31 43` = "111C") (`c07f1cea`–`c07f1d08`, `c04e0f78`, `c01d1100`). Metadata whitening at open is taken **from the signature flag 0x10000** → `FIL[0x50](1)` else `FIL[0x50](0)` (`c07f1d20`–`c07f1d68`). `VFL_Init(FPart)` (`c07f20d2`).
8. Sig found and sig byte0 != current epoch ('1') → "Epoch update in progress": `FIL[0x40](0x64)`, `WriteSignature(NULL,0)` (**erases** the signature block), `c0816280=1` so that `andGetStruct(0x10000001)` (`c07f1738`) later rewrites the signature — this is what `restored_external`'s `end_nand_epoch_update` triggers via `IOConnectCallMethod(sel 0x10000001)` (rd `0x5300`–`0x5364`).
9. Format branch `!(verified && sigfound)` (`c07f1e02`): if DT whitening → "[WMR:INF] Formatting with metadata whitening" `FIL[0x50](1)`; `!verified` → "[WMR:INF] Calling VFL_ProductionFormat()" = `FPart[0]()` (`c07fe4c4`, must return 1) else "[FTL:MSG] Calling VFL_FactoryReformat()" = `WriteSignature(NULL)` + `FPart[4](0,0)` (`c07fef14`). Then `VFL[0]()` = `VSVFL_Format` (`c07fc590`) → "VFL_Format [OK]"; (burn-in only with bit4); YAFTL registered (`c07ff1c0` → `c08164d8`); `FTL[0](VFL)`=`YAFTL_Init` (`c0804d58`); `FTL[0x18]()`=`YAFTL_Format` (`c0800b34`) → "FTL Format [OK]"; builds signature at `c0816394`: `+0 nSig`, `+4 flags = 5 | (DT whitening ? 0x10000 : 0)`, `+8..+0x108` = up to 0xff bytes of the kernel `version` string (`c04e0f71` returns `c021475c` = "Darwin Kernel Version 10.3.1: Mon Mar 15 23:15:33 PDT 2010; root:xnu-1504.2.27~4/RELEASE_ARM_S5L8930X") zero padded; `WriteSignature(buf,0x108)` → "Write Signature OK", read back + memcmp → "Read back Signature OK" (`c07f1f0c`–`c07f1faa`).
10. `VFL[0x18]()`=`VSVFL_Open` (`c07fc930`) → "VFL_Open [OK]"; FTL chosen by `VFL.GetDeviceInfo(0x71)` (= VFLCxt `ftl_type`) == 2 → YAFTL (`c07f2050`); `FTL_Init`; `FTL[4](pTotal,pBytes, flags>>7&1)` = `YAFTL_Open` (`c080349c`) → "FTL_Open [OK]".

VSVFL geometry `c081674c` (`VSVFL_Init c07fcdb8`, `c07f97fc`): `+0` pages/block, `+4` CS, `+6` blocks/CS, `+8` blocks/bank(VFL) = blocks/CS ÷ banks, `+0xa` banks/CS phys, `+0xc` bank addr space, `+0x12` pages/sublk = ppb×CS×banks, `+0x14` bytes/page, `+0x16` banks total, `+0x18` VFL banks/CS, `+0x1a` block offset (=1). Vendor 0x100014/0x120014/0x140014 → **2 VFL banks/CS**, C2P: `pblock = 2*vblock + (vbank/CS & 1)`, P2C: `vpage = (ppage%ppb) | ((ppage & ~(2ppb-1))>>1)`, `vbank = cs + (ppage & ppb ? CS : 0)` (`c07f9300`, `c07f9360`); 0x10013/0x120013/0x140013 → 4 banks; 0x170015 etc → 1.

## 2. What VFL_ProductionFormat writes (special pages, DEVICEINFOBBT, NANDDRIVERSIGN)

`VFL_ProductionFormat`/`VFL_WriteInitialBBT` (`c07fe4c4`–`c07fee84`, FPart.c) per CS:
1. `_ReadSpecialBlock(cs,"DEVICEINFOBBT")` — if found: "found BBT in Block0, but not SpecialBlocks", skip CreateBBT.
2. `_CreateBBT`: for every block (all banks) read pages with `FIL.ReadNoECC` ([0x8]) per algorithm type `devinfo+4` ∈ 1..9 (`tbh` at `c07fe664`): checks first/last page data/spare bytes for 0xFF (e.g. type 2: page 0 and page ppb−1, data[0]==0xFF && spare[0]==0xFF). **A fully 0xFF NAND yields zero bad blocks for every type**. Unknown type → "Unknown initial bad block algorithm type" → fail.
3. BBT bitmap = `ceil(blocks_per_CS/8)` bytes, bit=1 good; **block 0 bit cleared** (`c07fe9a0`).
4. Header (0x38 B, stack `sp+0x4c`): `+0 "DEVICEINFOBBT"` NUL-padded to 16, `+0x10 u32 = 4`, `+0x14..+0x33` = 0xFF (later overwritten by the candidate list), `+0x34 u32 = payload length` (BBT bytes). `_WriteSpecialBlock(cs, block 0, hdr, bbt)` ("updating block 0"), ignoring failure.
5. Candidate count: CS0 → 3 (+2 because FPart opt bit0 is always set → **5**) (+2 if diag-bits); other CS → **2** (`c07fea2c`–`c07fea54`). `testSpecialBlockCandidate` from the **highest block downward**: skip BBT-bad; erase, write all `ppb` pages with a test pattern, read back all, erase (`c07fea62`–`c07fec78`). Good candidates go to `hdr+0x14+4*i` (u32) and are **marked bad in the BBT**; failing ones are marked bad in a scratch copy.
6. BBT (with the candidate list in its header) written to `cand[0]` and again to `cand[1]` (`c07fee14`, `c07fecd6`), cache entries added (`c07fed8a`).
7. After all CS succeed: `FIL.Erase(cs, block 0)` for every CS (`c07fedd0`–`c07fedf8`). So block 0 ends up **erased and marked bad**.

`_WriteSpecialBlock(cs, block, hdr, data, len)` (`c07fd37c`): `FIL.Erase(cs,block)`; page 0 = `hdr[0x38] || data[0 .. min(len, bpp-0x38))`, continuation pages hold the rest; spare buffer memset 0 (12 B) (`c07fd41e`); each page written with `FIL[0x38]` (`c07ef844`), read back with `FIL[0x14]` (`c07f02a4`) and memcmp'd; 4 attempts. Special pages go through the normal AES path with **data whitening on** (`FIL[0x4c](1)` in `c07fdba4`/`c07fe19c`), i.e. META-key encrypted, IV=LFSR(physical page) (META key `92a742ab08c969bf006c9412d3cc79a5` found only inside the IOP firmware blob at `c075b064`; FS key `f65dae950e906c42b254cc58fc78eece` = first 16 bytes of AppleNANDFTL `__data` `c08157bc`).

`_ReadSpecialBlock` (`c07fda18`): cache first; else scan blocks `blocks_per_CS-1` down to `blocks_per_CS - blocks_per_CS/10` (`c07fdb60`: udiv by 10), pages 0.. until magic (16 B memcmp) matches or 3 read failures/block (`c07fd9bc`); copies header, then `min(hdr+0x34, maxlen)` payload bytes across pages. When the found magic is DEVICEINFOBBT on CS0 it registers `hdr+0x18`→DEVICEINFOBBT, `+0x1c`,`+0x20`→DEVICEUNIQUEINFO, **`+0x24`→NANDDRIVERSIGN**, `+0x28`,`+0x2c`→DIAGCONTROLINFO; other CS: `+0x18`→DEVICEINFOBBT (`c07fdaf6`–`c07fdb46`).

**Resulting positions for 0x7294D7EC ×4 (0x1038 blocks/CE, no bad blocks)**, all in CS-physical block numbers, page 0:
- CS0: BBT copies at **0x1037** and **0x1036**; cand[2]=0x1035, cand[3]=0x1034 reserved for DEVICEUNIQUEINFO (never written on iPad — sysconfig lives in NOR), **NANDDRIVERSIGN at 0x1033** (WriteSignature `c07fdc3c` writes into the cached cand[4] block; erase + page 0); cand[5],[6]=0xFFFFFFFF (DIAGCONTROLINFO absent). BBT header: `+0x14=0x1037,+0x18=0x1036,+0x1c=0x1035,+0x20=0x1034,+0x24=0x1033,+0x28=+0x2c=0xFFFFFFFF`, `+0x34=0x207`.
- CS1..3: BBT at **0x1037** and **0x1036**; header `+0x14=0x1037,+0x18=0x1036`, rest 0xFF.
- Bits cleared in each BBT: block 0 plus the candidate blocks (CS0: 0x1033–0x1037; others: 0x1036,0x1037).
- For 0xB614D5AD ×4 (0x1000 blocks): same with 0xFFF..0xFFB / 0xFFF,0xFFE; BBT length 0x200.

**NANDDRIVERSIGN payload (0x108 B, in the special page after its 0x38 header with `+0x34 = 0x108`)**: `u32 nSig = 0x43313131`, `u32 flags = 0x00010005` (DT `metadata-whitening=1` in `dt.txt` line ~300; `default-ftl-version=1`), `char version[0x100]` = the Darwin version string above. Reader only validates nSig bytes and the 0x10000 bit (§1 step 4/7); bytes +8.. are never checked.

`DEVICEUNIQUEINFO`/`DIAGCONTROLINFO`: **not** written on this path (FPart functions exist, used only via user-client calls). DEVICEINFOBBT **is required** at open: `IsProductionFormatVerified` and `VSVFL_Open`'s `VFL_ReadBBT` (`c07fc940`) fail without it on any CS.

`VFL_FactoryReformat(eraseAll, eraseBlock0)` (`c07fef14`): needs BBT on every CS; erases every good block from `c0816890`(=1) (bank 0) / 0 (other banks) with 3 retries; optional block-0 erase — what `nand-wipe` effectively runs.

## 3. VSVFL_Format (`c07fc590`) — exact fresh context

Per CS (`VFLCxt[cs]` at `c08166f8 + cs*0x800`, memset 0):
- `vendor_type` (`+0x6da`) = `FIL.GetDeviceInfo(0x6b)` (0x100014 for the Samsung parts).
- `usable_blocks_per_bank` (`+0x696`) = `reserved_block_pool_start` (`+0x698`) = `(0x3D0 << (floor(log2(blocks_per_bank_VFL)) - 10)) & 0xffff` (`c07fc5e8`–`c07fc60c`).
  - 0x7294D7EC: blocks/bank = 0x1038/2 = **0x81C** → log2=11 → **0x7A0 (1952)**; pool = 0x7C (124) blocks/bank.
  - 0xB614D5AD: 0x1000/2 = 0x800 → **0x7A0**; pool = 0x60 (96).
  - (8-CE parts identical per bank; 0x72D5DEEC 0x2070/2=0x1038 → log2=12 → 0xF40.)
- `version` (`+0x7f4`) = 2; `control_block[3]` (`+0x69a`) = **{0,1,2}** (virtual blocks); `+0x10` = number of BBT-bad blocks (CS0: 6, others: 3); `usn_block`/`usn_page` (`+0xc/+0xe`) = 0.
- `vfl_context_block[4]` (`+0x68e`) = first four BBT-good physical blocks ≥ 1 (scan limit block 1+0xC7=200), each erased (4 tries) → **{1,2,3,4}** (`c07fc6b0`–`c07fc752`).
- `reserved_block_pool_map` (`+0x26`, u16[820]): index `bank*(blocks_per_bank − pool_start) + i`, value **0xFFF0** for a good spare vblock `pool_start+i`, **0xFFFF** for a BBT-bad spare (`c07fc7d8`–`c07fc7d6`). Then `_ReplaceBadBlk(cs, pbn)` (`c07f9cdc`) for pbn = 0..`vfl_context_block[3]` (=0..4): each takes the next free slot of its bank (`slot = replaced_block_count[bank]` at `+0x16+2*bank`, u16) and stores the **physical block number**; then any other BBT-bad block below pool_start (none). Result for the Samsung layout (bank0 = even pblocks): bank0 map[0..2] = {0,2,4}, `+0x16`=3; bank1 map[124+0..1] = {1,3}, `+0x18`=2; CS0 bad spares → 0xFFFF at bank0 slots 0x7a,0x7b (pblocks 0x1034,0x1036) and bank1 slots 0x79,0x7a,0x7b (0x1033,0x1035,0x1037); CS1..3: bank0 slot 0x7b, bank1 slot 0x7b.
- `total_reserved_blocks`/`num_reserved_blocks`/`scrub_list`/`+0x6ca..+0x6d9` = 0.
- Checksums (`c07f8eac`): `+0x7f8 = Σ u32[0..0x7F8) + 0xAABBCCDD`, `+0x7fc = ⊕ u32[0..0x7F8) ^ 0xAABBCCDD` (both must match at open, `c07f8ee0`).
- `_StoreVFLCxt` (`c07fab08`) → `_WriteVFLCxtToFlash` (`c07fa7b4`): `usn_dec` (`+4`) **decremented** (0 → 0xFFFFFFFF), global `c08167b8` incremented and stored to `usn_inc` (`+0`) → CS0..3 get 1..4; 8 identical copies of the 0x800 struct at pages `usn_page..usn_page+7` of `vfl_context_block[usn_block]` (block 1, pages 0–7), each with spare = `{u32 usn_dec, 0xFF×4, [8]=0x00, [9]=0x80, 0xFF,0xFF}`; read back and compared over 0x6E0 bytes + spare; `usn_page += 8`. `YAFTL_Format` ends with `VFL_SetStruct(0x02000c00, {2})` → `ftl_type (+8) = 2` and another `_StoreVFLCxt` → a **second copy set at pages 8–15** (usn_inc 5..8, usn_dec 0xFFFFFFFE). A generator can emit a single copy set (pages 0–7) with `ftl_type=2` directly.

## 4. YAFTL_Init / YAFTL_Format / YAFTL_Open

`YAFTL_Init` (`c0804d58`), geometry `c0815ae4`: `[0]`=VFL.GetDeviceInfo(0x6e)=pages/sublk, `[2]`=(0x70)=`usable_blocks_per_bank` (numBlocks), `[8]`=(0x68) bytes/page, `[0xa]`=(0x6f) banks total. `tocPagesPerBlock = ceil(4*ppsublk/bpp)`, `tocEntriesPerPage = bpp/4`, `numIBlocks = 3*ceil((numBlocks-8)/tocEntriesPerPage)`, `totalPages = (numBlocks-8)*(ppsublk-toc) - numIBlocks*ppsublk`, `tocArrayLength = ceil(ppsublk*numBlocks*4/bpp)`, `nPagesTocPageIndices = ceil(tocArrayLength*4/bpp)`, `nPagesBlockStatuses = ceil(numBlocks/bpp)`, `nPagesBlockReadCounts = ceil(2*numBlocks/bpp)`, `nPagesBlockEraseCounts = ceil(4*numBlocks/bpp)`, validI/validD pages = readCounts pages, `ctrlBlockPageOffset = Σ six + 2*toc + 2` (`c0804f4a`–`c080517c`):

| chip | ppsublk | bpp | numBlocks | toc | tocEntries | numIBlocks | totalPages | tocArrayLen | idx/stat/rc/ec/vI/vD pages | ctrlBlockPageOffset |
|---|---|---|---|---|---|---|---|---|---|---|
| 0x7294D7EC ×4 | 1024 | 8192 | 1952 | 1 | 2048 | 3 | 1,985,640 (15.15 GiB) | 976 | 1/1/1/1/1/1 | **10** |
| 0xB614D5AD ×4 | 1024 | 4096 | 1952 | 1 | 1024 | 6 | 1,982,568 (7.56 GiB) | 1952 | 2/1/1/2/1/1 | **12** |

Block device: `*pBytesPerPage = bpp`, `*pTotalPages = (totalPages-1)/100 * 99` (`[0x120]`=0x63) (`c08038bc`) → 1,965,783 × 8 KiB (15.0 GiB) resp. 1,962,742 × 4 KiB.

`YAFTL_Format` (`c0800b34`): reads `control_block` via `VFL[0x2c]`; if an old `CX01` exists it recovers statistics; then `VFL_Erase(vbn,1)` for **all** `vbn = 0..numBlocks-1` (each = 8 physical blocks); writes a new context **only if an old one existed**; sets `ftl_type=2`. So after a fresh format the 3 ctrl blocks are erased and the first `YAFTL_Open` takes the restore path.

`YAFTL_Open` (`c080349c`): ctrl blocks = `control_block[3]` (status 2); page 0 of each read (`c07ff21c`); pick block with max spare usn (u32 at spare+4); a block whose page 0 gives a real read error is **erased** (`c080363a`); slots of `ctrlBlockPageOffset+1` pages: valid slot ⇔ first page reads OK, spare type (`spare[9]`) 0x20, data starts "CX01", and page `slot+ctrlBlockPageOffset` is **clean**; wrong magic on a readable ctx page → "YAFTL_OPEN unsupported low-level format version" → **fatal** (`c07ffb6a`, `c0803784`). `readCXTInfo` (`c07ffb20`) requires type 0x20 on every ctx page and loads: `+0x5e→[0x48] toc`, `+0x60→[0x4a]`, `+4→numIBlocks`, `+8→totalPages`, `+0x5c→tocArrayLength`, `+0x62/0x64`, `+0xc latestUserBlk`, `+0x66 pagesUsedInLatestUserBlk`, `+0x1c numAvailable`, `+0x14 latestIndexBlk`, `+0x18`, `+0x68`, `+0x20 numIAvailable`, `+0x24 numAllocated`, `+0x28 numIAllocated`, `+0x10 maxIndexUsn`, `+0x95`, `+0x30`, `+0x2c`, `+0x94` (=99); then user-TOC pages, index-TOC pages, stats page (`_FTLSetStatisticsFromCxt`), tocPageIndices, statuses (u8), readCounts (u16), eraseCounts (u32), validPagesINo, validPagesDNo. Context page layout as written by `writeCxt` (`c0800344`): page0 header, `toc` user-TOC pages, `toc` index-TOC pages, stats page (`YAFTLStats[0x78] @0`, `VFL GetStruct(0x02000200) @0x200`, `GetStruct(0x02000500) @0x400`, **u32 0x00010002 at bpp−4**), then the arrays. Every ctx page spare: `{lpn=garbage, usn=++[0x60], [8]=?, [9]=0x20}`.
No valid ctx (or `nand-force-restore`) → "CXT is not valid. Performing full NAND R/O restore": `FIL[0x40](2)`; every non-ctrl block: page 0 read → error → scan; all-error → **VFL_Erase**; clean (type 0xFF, lpn 0xFFFFFFFF) → free; type 0x4 → index list; type&0x10 → user list; anything else → "block that does not belong to anything … probably need to erase" → **VFL_Erase** (`c0803ab4`–`c0803c36`). On failure: "Read only full restore failed. Performing full NAND R/W restore". The new context is not written by Open itself (only `YAFTL_GetStruct/flush` `c08030d8` if `[0x11c]` changed); it is written by `YAFTL_Flush` (`c080344c`) on later syncs.

## 5. Hardware operations issued by the format / open paths (IOP model requirements)

All NAND I/O goes `AppleNANDFTL FIL → IOFlashStorageDevice (AppleS5L8920XIOPFMI) → IOP mailbox` (`_fmiExecuteCommandLocked c04e99bc`). IOP command buffer is 0x200 B zeroed with `u32 opcode` at +0 (`_fmiInitCommand c04e8084`). Opcodes used by the kext: **1** SET_CONFIG per bus (`c04e80a0`: +0x14/+0x18 bus regs, +0x1c bytes/page, +0x20 sectors, +0x24, +0x28 meta, +0x2c=1, +0x30..+0x40 timings), **2** RESET+READ_ID (`c04e8500`: +0x10 = phys addr of 0x50-byte ID buffer per bus, 16 CE × 5 B; chip ID compared to `[0xbc]`), **3** ERASE single (`c04e8144`: +0x10 CE, +0x14 page), **0xc** ERASE multiple (`c04e8a94`, bank list), **8** READ / **9** WRITE DMA-list (`c04ea510`: opcode = op+8; +0x4 flags (bit0, bit2 AES, bit3), +0x10 page count, +0x14/+0x18 DMA list phys, +0x1c..+0x28, +0x2c meta buffer, +0x30/+0x34 AES key type 1..6 (1 = AES-128 custom key copied to +0x38 from devinfo+0x44 → the FS key), +0x58 whitening enable, +0x68/+0x6c CE-status array 0x30 B), **7** raw read / **5** raw write (`c04e83b4/c04e83c4`), **0xb** READ_BOOTPAGE / **0xa** WRITE_BOOTPAGE (`c04e8262`, 0x600 B). Meta-whitening LCG constants (0x19660D @`c04e71ac`, 0x3C6EF35F @`c04e71b0`, seed 0x50F4546A @`c04e71dc`) live in the **IOPFMI kext** (`c04e7144`/`c04e71b4`).

Operations the kernel self-format issues on a blank 16 GB image: ReadNoECC of 2 pages × 4152 blocks × 4 CE (bad-block scan); per candidate: erase, 128 page writes, 128 reads, erase (5+2+2+2 candidates); BBT writes/verifies (block 0 + 2 copies per CS); block-0 erase ×4; VFL: 4 block erases + 16 page writes/reads per CS (×2 sets); YAFTL_Format: **1952 × 8 = 15,616 block erases** (via EraseMultiple if cap 0x40); signature erase/write/read; then restore reads page 0 of 1952 vblocks. Any rw mount later needs program/erase too.

## 6. restored_external / rc.boot / options / MBR / EncryptedBlockStorage

- `rc.boot` is a Mach-O (not a script): mounts, `execl` `/usr/local/bin/restored_external` (then `restored_update`, `restored`, `/usr/libexec/ramrod/ramrod`), `reboot`.
- `options.plist`: `SystemPartitionSize = 1000` (MiB). restored_external steps (`0x547c`): `WipeStorageDevice`(default 0), `CreateFilesystemPartitions`(1), `SystemImage`(1), `FlashNOR`(1), `UpdateBaseband`.
- `partition_nand_device` (`0x6f98`): only if `IOFlashController` has `boot-from-nand`; iPad → skipped (no `ioflashstoragetool format`).
- `end_nand_epoch_update` (`0x5300`): `IOServiceOpen(AppleNANDFTL, type 0x20)`, `IOConnectCallMethod(0x10000001)` → kernel `c07f1738` re-reads/writes the signature.
- `create_filesystem_partitions` (`0x6458`): waits for `IOMedia` "BSD Name" match; reads AppleNANDFTL `encryptable` (bool) → `EncryptDataPartition` default; `sizeSectors = SystemPartitionSize << 11` (=2,048,000 512-B units); `MKMediaCreateWithPath("/dev/disk0")`, `MKCFBuildPartition` ×2 with `Minimum One Block Gap`/`Sectors/Track Alignment`/`Sectors/Cylinder Alignment` = false: partition 1 `Apple_HFS` of `sizeSectors`, partition 2 `Apple_Encrypted` (if encrypted) else `Apple_HFS`, remaining; `MKCFCreateMap(type 8)`, `MKCFWriteMedia` (MBR); waits for the data media (`/dev/disk0s2s1` if encrypted else `/dev/disk0s2`), wipes 1 MiB of 0xFF at its start and at its end (`0x6a84`–`0x6b96`), then `newfs_hfs` (journaling per `/chosen/data-journaling`). `restore_images` (`0x5fe4`): `/usr/sbin/asr -source asr://localhost:12345 -target /dev/disk0s1 -erase -noprompt --chunkchecksum --puppetstrings`. `modify_fstab` (`0x5c00`): rewrites `/dev/disk0s2`→`/dev/disk0s2s1` when encrypted, root `ro`/`rw` per `ReadOnlyRootFilesystem`. Root fstab in the IPSW rootfs: `/dev/disk0s1 / hfs ro 0 1` / `/dev/disk0s2 /private/var hfs rw,nosuid,nodev 0 2` (`fw/7B367-dec/fstab`).
- MBR type → content hint table (IOFDiskPartitionScheme personality in prelink info): **0xAF=Apple_HFS, 0xAE=Apple_Encrypted, 0xAB=Apple_Boot, 0xA8=Apple_UFS, …**. `EncryptedMediaFilter` matches `Content Hint = Apple_Encrypted` and publishes a child `Apple_HFS` IOMedia of `size − 1 block` (`c04d9060`–`c04d90fa`); key block = last block: `'tprc'` then AES-CBC(key 0x89B, decrypt flag 1) of 0x40 bytes at +4 = `'TPRC' | u64 media size | 0xFFFFFFFF | key[32] | u32 0x20` (`c04d961c`–`c04d9752`); with `nand-enable-reformat` and no valid key block it **creates a new random key block** (`c04d9484`, random via `c006bf81`) (`c04d9890`–`c04d98b8`). Key 0x89B seed `183e99676bb03c546fa468f51c0cbd49` at `c044e384`. A **single 0xAF (Apple_HFS) partition with a rw root** is fully accepted (nothing in the kernel requires 0xAE; the 0xAE path is purely restored_external's choice).

## 7. Generator specification (option A), field by field

Image geometry: 4 CE × 0x1038 blocks × 128 pages × (8192 + 12 meta) (or 0xB614D5AD: 0x1000 × 128 × (4096+12)); chip ID must be one of the IOPFMI-supported IDs (`c04ed868` error otherwise), 2 buses, CEs interleaved as in openiBoot `h2fmi_init_virtual_physical_map`. Everything not listed = erased (0xFF data, 0xFF meta).
1. **DEVICEINFOBBT** on every CE: CS0 blocks 0x1037 and 0x1036, page 0; CS1–3 blocks 0x1037,0x1036: `hdr{magic,4,cand[8],len=0x207}` + bitmap (bit=1 good; clear bit 0 and the candidate blocks); data META-encrypted (IV=LFSR(phys page)), meta 12×0x00 (whitened); optional block-0 copy not needed.
2. **NANDDRIVERSIGN** CS0 block 0x1033 page 0: `hdr{magic,0,…,len=0x108}` + `{0x43313131, 0x00010005, version[0x100]}`.
3. **VFLCxt** per CE: block 1 pages 0–7 identical 0x800 structs (§3 values, `ftl_type=2`, `usn_inc`=1..4, `usn_dec`=0xFFFFFFFF, version 2, checksums), spare `{FF FF FF FF, FF FF FF FF, 00, 80, FF, FF}` (usn_dec bytes) META-encrypted; blocks 2,3,4 erased.
4. **YaFTL**: ctrl vblocks 0,1,2 (physical: vblock v of vbank b → CE `b%4`, pblock `2v + (b/4)`): one ctx slot at ctrl vblock 0 pages 0..ctrlBlockPageOffset (10 or 12): page 0 `CX01` + fields above (numIBlocks, totalPages, tocArrayLength/toc/tocEntries, latest user/index blk, counters, `+0x94=0x63`), TOC pages, stats page (zeros + `0x00010002` at end), tocPageIndices (0xFFFFFFFF for unmapped), statuses (0xFF free, 1 allocated user, 0x40 allocated index, 2 for the 3 ctrl blocks, 0x10 for the current ctrl block), read/erase counts 0, validPagesI/D; page `slot+ctrlBlockPageOffset` clean; all ctx pages spare type 0x20, usn ascending. Index blocks: type 0x4, lpn = TOC page number, data = tocEntriesPerPage u32 vpns; user blocks: type 0x10, lpn, usn; closed blocks end with `toc` BTOC pages (u32 lpn per page, spare type 0x8 (user) / 0xC (index)). User data AES FS-key IV=LFSR(LPN); everything else META key IV=LFSR(phys page); all meta whitened with the LCG table (page-indexed). Alternatively (option A-lite) omit the ctx entirely and let the R/O restore rebuild it from page-0 spares/BTOCs — it only erases blocks whose page 0 is neither clean nor type 0x4/0x10.
5. **Block device content**: MBR at LPN 0 (units = FTL page size, 8192 B), one entry type 0xAF, HFS+ root with rewritten fstab (`/dev/disk0s1 / hfs rw`), or two entries 0xAF+0xAE with a `tprc` block (needs UID-derived 0x89B in the generator).

Compared with the iPod `imgtools/build_nand.py` (older VFL/FTL, 4 KiB pages, 64-B spare), the new pieces are: special pages with the 0x38 header at the top blocks, VSVFL 2-bank interleave + pool map, YaFTL `CX01` layout, 12-byte whitened meta, and two AES domains.

## 8. Recommendation

- **Generator (A)**: all "unknown" values are now derived from the kernel itself (§2–§4, §7); the remaining risk is byte-level details that the kernel does not validate (special-page meta content, stats page, exact candidate list) — the kernel tolerates them. Cost: extend `build_nand.py`/`pack_nand.py` (sparse 8 KiB-page format). Emulator needs: H2FMI/CDMA (for iBoot) + IOP FMI HLE opcodes 1,2,3,0xc,8,9 (+5,7,0xa,0xb) with AES (FS key from command, META key fixed) and whitening semantics, including program/erase.
- **Kernel self-format (C)**: works with a blank image + `nand-enable-reformat=1` (no restored_external), but leaves an *empty* FTL (no MBR/HFS); combine with the generator or use it as the reference to diff the generator's VFL/FPart output in the emulator. It requires ReadNoECC, erase-multiple and ~15.6k block erases through the IOP model — so it doubles as the IOP write-path test.
- **Full restore (B)**: needs DFU/iBSS/iBEC USB, restore-mode `com.apple.mobile.restored` protocol over usbmuxd, the 3.2 ramdisk boot, MediaKit MBR + asr; provides nothing beyond §6. Not recommended.
