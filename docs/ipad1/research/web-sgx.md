# SGX535 / GPU stack research for iPad1,1 iOS 3.2 (7B367) — findings

All firmware facts below were read out of the decrypted 7B367 images in the scratchpad (`/tmp/claude-0/-home-user/2fb4038f-ca86-59b7-95f7-7e88ca8c44ec/scratchpad/`, abbreviated `$SP`), using public keys from `https://api.ipsw.me/v4/keys/ipsw/iPad1,1/7B367`. Nothing under `/home/user/*` was modified.

## 1. iOS 3.2 GPU software stack on A4 (what actually ships)

### 1.1 Kernel side (kernelcache.release.k48, decrypted+LZSS'd: `$SP/dec/kernelcache.k48.mach`, 9,375,697 B)
- **Kext:** `com.apple.IMGSGX535` v38.10, `CFBundleName` "IMG SGX535 Graphics Kernel Extension", `_PrelinkExecutableLoadAddr 0xc0690000`, size `0x22000`, `_PrelinkKmodInfo 0xc06b16d0`, built from `GraphicsDriversES-38.10/drvIMG/GLKernel/SGX/` (prelink plist in kernelcache; source paths in kext strings, e.g. `IMGSGX_accelerator.cpp:5687`). - **Personality `IMGSGX535-H2`** (kernelcache prelink XML):
  `IOClass=SGXDriver`, `IOProviderClass=AppleARMIODevice`, `IONameMatch=sgx,s5l8920x`, `IOMatchCategory=IOAcceleratorES`, **`IOGLESBundleName=IMGSGX535GLDriver`**, **`IOGPUBlitBundleName=IMGSGX535GPUBlitDriver`**, `IOSourceVersion=38.10`.

### 1.3 Userland (root filesystem 018-7223-007.dmg, decrypted to `$SP/fw/7B367-dec/rootfs.hfsx`; volume name `Wildcat7B367.K48OS`)
- `/System/Library/Frameworks/OpenGLES.framework/` contains **only** `Info.plist` (CFBundleVersion 1.6.6, "OpenGLES 1.6.6.11.0") and **`GLEngine.bundle/GLEngine`** (1,034,960 B, armv7). **There is no `MBXGLEngine.bundle` on the iPad 3.2 root FS.** `libGFXShared.dylib`, `libGLImage.dylib`, `libGLProgrammability.dylib` are referenced by GLEngine but live only in `dyld_shared_cache_armv7`.
- **`/System/Library/Extensions/IMGSGX535GLDriver.bundle/IMGSGX535GLDriver`** (682,992 B, armv7, `com.apple.IMGSGX535GLDriver` 38.10, `DTSDKName iphoneos3.2.internal`). It is a **gld plugin**: 83 exports, all `_gld*` (`gldInitializeLibrary`, `gldCreateContext`, `gldAttachDrawable`, `gldCreateShared`, `gldCreatePipelineProgram`, `gldLoadTexture`, `gldGetRendererInfo`, `gldFlush`, `gldFinish`, …). It talks to the kernel through IOKit only (`IOServiceNameMatching`, `IOServiceGetMatchingService`, `IOServiceOpen`, `IOConnectCallMethod/ScalarMethod/StructMethod`, `IOConnectMapMemory`, `IOConnectAddClient`) and contains the whole PowerVR userland: `PVRUniFlexCompileToHw`, `sgxGenerateVertexPDSUnpackNative`, `sgxCreateEOPEventUSEProgram`, PVRTC formats, feature tables `_g_sSGX535_107_To_109_Features_Table` and `_g_sSGX535_110_To_Head_Features_Table` (also 520/530/531/540/543/545 tables), renderer strings `"OpenGL ES-CM 1.1 IMGSGX535-38.10"`, `"OpenGL ES 2.0 IMGSGX535-38.10"`, `"PowerVR SGX 535"`, env var **`GL_REJECT_HW`**.
- **ES 1.1 and ES 2.0 are not separate bundles.** One GLEngine (Apple's, `OpenGL-6.6.11/GLEngine/gle/gle_cmd_processor.c`, exports `_es1_engine_extensions` / `_es2_engine_extensions`) plus one gld driver serve both.

### 1.4 How OpenGLES.framework 1.6.6 picks the engine (disassembly of the 7B367 OpenGLES image, `$SP/dec/OpenGLES.dis`, VA base 0x30232000)
Function at **0x30236f7x–0x3023726x** (cstrings at 0x30247b04..0x30247b80: `com.apple.opengles`, `GLEngine`, `GLEngine.bundle`, `gliInitializeLibrary`, `IOAcceleratorES`, `AppleMBXDevice`, `MBXGLEngine`, `bundle`, `GLESGetEGLInterface`):
1. Builds the path of `GLEngine.bundle` inside `com.apple.opengles` and `dlopen(path, 5)` (0x30237062). If dlopen fails → jump to legacy path (0x30237130).
2. `dlsym(h, "gliInitializeLibrary")` (0x30237076).
3. `IOServiceGetMatchingService(..., IOServiceMatching("IOAcceleratorES"))` (0x30237088–0x30237092). If a service exists: `gliInitializeLibrary(&g_accel, 0, 1, callback_0x30236d8c)`, else `gliInitializeLibrary(0,0,0,callback)` (0x302370b0–0x302370d2).
4. dlsym's a fixed table of **17 `gli*` entry points** (names at 0x30247bf4, 32-byte stride, stored at 0x3803645c): `gliChoosePixelFormat, gliDestroyPixelFormat, gliQueryRendererInfo, gliDestroyRendererInfo, gliCreateContext, gliDestroyContext, gliAttachDrawable, gliAttachDrawableWithOptions, gliSwapBuffers, gliSetInteger, gliGetInteger, gliGetAttribute, gliSetAttribute, gliCopyAttributes, gliGetVersion, gliBindViewES, gliPresentViewES`. Any missing symbol → dlclose and fall through.
5. Calls entry #14 (`gliGetVersion`) (0x3023711a–0x3023711e); non-zero return = GLEngine path selected.
6. **Legacy path (0x30237130–0x3023720e):** `IOServiceGetMatchingServices(IOServiceMatching("AppleMBXDevice"))`; requires at least one such service (`IOIteratorNext` result checked at 0x3023717a); then `CFBundleGetBundleWithIdentifier("com.apple.opengles")` → `CFBundleCopyResourceURL(…, "MBXGLEngine", "bundle")` → `CFBundleCreate` → `CFBundleGetFunctionPointerForName(bundle, "GLESGetEGLInterface")` → call it and cache the returned table (0x302371ec–0x302371f4). This is the iPod-era ABI qemu-ios's `contrib/it-gles/mbxshim.c` implements; on the iPad it is dead code unless (a) `GLEngine.bundle` is absent/fails and (b) an IOService of class `AppleMBXDevice` exists (none in the 7B367 kernelcache).
- The gl* trampolines in 3.2 are: `mrc p15,0,r3,c13,c0,3; ldr r3,[r3,#0xc0]` (**TSD slot 48**, was slot 30/#0x78 in the 3.1.3 iPod framework per mbxshim.c), `ldr r0,[r3,#0xc]` (GC), `ldr r3,[r3,#0x10+slot*4]; blx r3` (e.g. 0x30233424–0x30233438) — same ctx layout (GC at +0xC, dispatch table at +0x10). 290 such trampolines. `-[EAGLContext initWithAPI:properties:]` still callocs a 0x19C0 (6592) byte context (0x30236176, 0x30236aa2).
- GLEngine → gld plugin binding: GLEngine imports `gfxGetPluginWithDriverID`/`gfxGetPlugins`/`gfxPluginConnectAll` from `libGFXShared.dylib`; the shared cache contains the strings `IOGLESBundleName` and `gldInitializeLibrary` (so libGFXShared reads the accelerator's `IOGLESBundleName` property and dlopens `/System/Library/Extensions/<name>.bundle`). Exact path-format string not found in the cache strings.

## 2. Can SpringBoard/CoreAnimation come up without a GPU on 3.2? Yes — software renderer is the fallback.

From the 7B367 QuartzCore image (`$SP/dec/QuartzCore.dis`, base 0x30951000; strings/selectors resolved through the shared cache):
- Environment variables QuartzCore 3.2 reads (cstrings 0x309dc41c..): `CA_ENABLE_OGL`, `CA_ENABLE_TILING`, `CA_DISABLE_RENDER`, `CA_DISABLED_EXTENSIONS`, `CA_DISABLE_DIRTY_REGIONS`, `CA_DISABLE_OCCLUSION_CULLING`, `CA_DISABLE_WORKAROUNDS`, `CA_ALWAYS_RENDER`, `CA_AUTO_FLUSH`, `CA_BENCHMARK`/`LK_BENCHMARK`, `CA_MAX_TEXTURE_SIZE`, `CA_MAX_TEXTURE_UNITS`, `CA_PRINT_*`, `CA_LOG_*`, `CA_COLOR_*`, `CA_RESIZE_YUV_SCALE`, `MBX2D_OFFSCREEN`, `MBX2D_PAGE_FLIP`. **`LK_ENABLE_OGL` does not exist anywhere in the 7B367 shared cache or SpringBoard binary** (`strings` of `dyld_shared_cache_armv7` and of `/System/Library/CoreServices/SpringBoard.app/SpringBoard` (1,366,768 B) find only `CA_ENABLE_OGL`); the `LK_` fallback is only implemented for `LK_BENCHMARK` (0x30953450: checks `CA_BENCHMARK` then `LK_BENCHMARK`).
- **`CA_ENABLE_OGL` semantics (0x309c7952–0x309c797c):** once-only: `v=getenv("CA_ENABLE_OGL"); flag = (v==NULL) ? 1 : (atoi(v)!=0)` stored at 0x38119b60. So on 3.2 **OpenGL compositing is on by default**; `CA_ENABLE_OGL=0` forces the software renderer. (qemu-ios sets `CA_ENABLE_OGL=1`/`LK_ENABLE_OGL=1` for the 3.1.3 iPod — `imgtools/bake-guest-tools.sh:77`; on 3.2 the `LK_` one is a no-op and `CA_ENABLE_OGL=1` equals the default.)
- **Renderer selection (0x309c7844):** if `display->renderer (this+0xfc)==NULL` and flag set → `[[EAGLContext alloc] initWithAPI:properties:]` with an `NSMutableDictionary` (`setObject:forKey:`) at 0x30974630 (classrefs resolved: `EAGLContext`, `NSMutableDictionary`; selrefs `alloc`, `initWithAPI:properties:`), then creates the OGL renderer (0x30974710) and stores it. If the EAGLContext is nil (no engine / no accelerator) or flag is 0, the caller (0x309c78c0) takes the **software path `bl 0x309c9f8c`**. Software-renderer existence also evidenced by `"CoreAnimation: %d by %d image is too large for software renderer, ignoring"` (0x309e038c, referenced at 0x309b9e8c).
- The SpringBoard launchd job on the 7B367 rootfs (`/System/Library/LaunchDaemons/com.apple.SpringBoard.plist`, `$SP/fw/7B367-dec/com.apple.SpringBoard.plist`) has **no `EnvironmentVariables`** at all (Label, KeepAlive, MachServices incl. `com.apple.CARenderServer`, ProgramArguments, UserName=mobile).
- Prior art confirming the same design on 3.x: devos50's iPod touch 1G/2G emulation boots to the home screen with `LK_ENABLE_MBX2D=0` and everything "rendered by the kernel/software" (https://devos50.github.io/blog/2022/ipod-touch-qemu/); qemu-ios docs record the 7E18 "forced software compositor" boot and that it cannot sample NV12 (`/home/user/qemu-ios/docs/ipod-media.md:257-262`).
- Consequence for the plan: with no working SGX, `EAGLContext` creation must **fail cleanly** (it will: GLEngine's `gliInitializeLibrary` gets no `IOAcceleratorES`, then the AppleMBXDevice fallback finds no service → `-[EAGLContext initWithAPI:]` returns nil). Setting `CA_ENABLE_OGL=0` in the SpringBoard job is the belt-and-braces way to skip the attempt.

### 3.2 Driver start sequence and what a stub must satisfy (IMGSGX535.kext, `$SP/dec/sgxkext.dis`)
1. `SGXDriver::start` (region c06945f0–c0694760): maps the provider's register range and stores the VA at `this+0x36c` (c0694688); immediately reads `CORE_ID`/`CORE_REVISION` (c06946c4/c6) and calls an `AppleARMIODevice` virtual (vtable+0x358) with `"hclk"` (c069f1b4) — the 64-bit result is converted with constants 0x77359400 (2e9) and 1000 (c06946ea–c069470e), i.e. it is the AHB clock rate used for timing, and looks up `function-perf_advise` (c0694714) from the DT node. **No comparison of CORE_ID/CORE_REVISION against a fixed value exists in the kext** (no `0x0113xxxx` immediates anywhere in `__text`); the values are only recorded. So any plausible pair (e.g. ID `0x01130000`, rev `0x00010201`) should pass the kext; the userland GLDriver selects a feature table by revision (`107_To_109` vs `110_To_Head`).
2. Also maps a **second MMIO window kept at `this+0x3fc`/`this+0x3f8`** (set at c0691c6a/c0692674; used in the power-up path c0691644–c0691680: `[base2+0x14] &= ~2; [base2+0] |= 2; … poll [base2+0] & 8`). Source of this mapping not resolved (sgx DT node has one `reg`; it is probably the pmgr/PRFA or a clock-gate register obtained through `function-perf_advise`/`clock-gates 0x5d`). **Open item for the machine model.**
3. Hardware init (c0691660–c06916e0): `EVENT_KICK=1`, wait `[base2]&8`, `BIF_CTRL=2` (PAUSE), poll `BIF_MEM_REQ_STAT==0` (loop via c06916a0), zero 0xA58/0xA68/0xA6C/0xA70/USE_CODE_BASE0/0xACC …
4. `SGXDriver::reset_sgx()` (c0693740–c06937f0; name string at c069f3d4): `BIF_CTRL` writes, fault clear (0x12), ack `EVENT_STATUS`→`HOST_CLEAR`, `STATUS2`→`CLEAR2`, poll `BIF_MEM_REQ_STAT==0`, `SOFT_RESET=0x7f`, `BIF_BANK`=0, `0xCA0=0xC07C`, `DIR_LIST_BASE0=<PD phys>`, `SOFT_RESET=0x7e`, then reprogram (c0693af0–c0693b7c): `USE_CODE_BASE0`, `EVENT_KICKER`, 0xA68/0xA6C/0xA70/0xA58, `0xACC |= 0x1000000`, `0x630=2`, `PDS_EXEC_BASE=0x20000000`, `HOST_ENABLE=this+0x484`, `HOST_ENABLE2=this+0x488`.
5. **Microkernel:** the USSE microkernel is embedded in the kext's `__data` (c06a2bbc, 0xebc8 = 60,360 B; 8-byte USSE instruction stream, entropy ≈4.1–4.5 bits/byte). Before upload the kext scans it (c06918fa–c06919b6) counting `str` instructions to registers, to list base (0xC84), to BIF_CTRL (0xC00), to USE code base (0xA0C–0xA48) and panics with `"SGX Microkernel: illegal instructions found"` (IMGSGX_accelerator.cpp:5687) if any found. The microkernel is started with `EVENT_KICK`; the kext then expects it to make progress through shared memory and raise interrupts: strings `"SGX: Microkernel unresponsive.\n"` (c069edb0, used at c0693df2), `"SGX: 5 second render policy.\n"` (c069edd0), `"SGX Hang. fSubmitStamp %d,  fCompletedStamp[0] %d, ui32Timestamp %d\n"` (c069edf0) followed by the register dump at c0693e46–c0693eac (reads 0x12C, 0x118, 0xC04, 0xC08, 0xCA8, 0x4E0, 0x4E4, 0xAA4, 0xAA8, 0xB08–0xB1C, 0xB2C, 0xAC0). The reference KM does the same: after `EVENT_KICK` it polls `SGXMKIF_HOST_CTL.ui32InitStatus` for `PVRSRV_USSE_EDM_INIT_COMPLETE` (`$SP/dec/sgxinit.c:390-450`), and its ISR reads `EVENT_STATUS & EVENT_HOST_ENABLE`, acks via `EVENT_HOST_CLEAR` (sgxinit.c:1248-1275).
6. IRQ: VIC line 47 (DT `interrupts=0x2f`); ISR path is the standard read-0x12C/0x118 → write-0x134/0x114 pattern (c069377e–c069378e, c0693e4a).
7. Interpretation for the stub: a register-level stub that (a) returns sane `CORE_ID/REVISION`, (b) returns 0 for `BIF_MEM_REQ_STAT`, (c) sets `[base2]&8` on power-up, and (d) never raises interrupts will let `SGXDriver::start` complete but the first submitted job will hit the "Microkernel unresponsive"/hang policy (timer-based, non-fatal reset). Faithful completion would need emulating the microkernel's host-memory writes (init status, completed stamps) by walking the BIF page directory at `0xC84`, i.e. more than the iPod's MBX completion shim (`/home/user/qemu-ios/hw/arm/ipod_touch_mbx.c`, which uses the same 0x12C/0x130/0x134 EUR_CR_EVENT layout, IRQ 0x35, bases 0x3B000000/0x39400000).
8. Simplest GPU-less strategy: make the `sgx` DT node absent/renamed (or make `IOSGX535` matching fail) so the kext never starts, then rely on §2's software renderer; for GL apps, replace `GLEngine.bundle/GLEngine` with a shim implementing the 17 `gli*` entries (§1.4) instead of the 3.1.3 `GLESGetEGLInterface` ABI, or patch the `AppleMBXDevice` matching to re-enable the legacy path with the existing `mbxshim`.

## 4. Prior art (GPU stubbed / CoreAnimation up)
