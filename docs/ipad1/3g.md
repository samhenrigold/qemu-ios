# The iPad's Wi-Fi + 3G model (issue 57 of LightTouchMac)

Both iPad 1 models are `iPad1,1`, board `k48ap`, and restore from the same IPSW: one kernelcache, one
DeviceTree, one rootfs. What makes a unit the 3G model is on the board, and the machine models it with
`baseband=on` (default off, the Wi-Fi model).

## What differs on the 3G board

- **The radio-present strap, GPIO 0x607.** iBoot-1219 (5.1.1, 0x5ff09098) pulls it and reads it before
  anything else radio-related. Low (the Wi-Fi unit): `Radio not detected.`, and the DT's baseband node gets
  `device_type` `AAPL,ignore`, so AppleBaseband never matches and CommCenter finds no modem. High: iBoot
  brings the radio up.
- **The modem: the 3GS's X-Gold, not the iPhone 4's.** The DT's `baseband` node is `baseband,n82` and spi2
  has `protocol-version 1`, `max-data-size 0x7f8` in 3.2.2, 4.2.1 and 5.1.1 (the 3GS's IFX framing; the
  iPhone 4 has version 2, 0x7fc). Same GPIOs as the N90: MRDY 0x605, SRDY 0x104, radio_on 0x101, bb_rst
  0x102.
- **iBoot talks AT to the modem over uart1 before the kernel** (0x5ff09614 on): `at`, `ate0`,
  `+xdrv=10,2`, the radio's nvram as `+xdrv=9,1,<block>` (three 512-byte blocks), `+xdrv=10,6`, `+cgsn`
  (the IMEI it writes into `baseband/device-imei`), `+xdrv=10,7`. Each reply line gets 1 s, and iBoot reads
  the Rx count as UFSTAT[3:0] | full << 4, the silicon's 16-byte FIFO. With the model's default 256-byte
  FIFO a reply over 15 bytes read as nothing: `Radio Failed to read block 0`, `Pinging Radio Failed`, and a
  dead radio. The kernel then resets the modem and uses SPI only.
- **GPS.** The DT's `gps` node (`gps,bcm4750`, on a UART) is the 3G model's Broadcom receiver, as on the
  N90; locationd picks it for `K48M`. Not modeled (`docs/baseband/gps.md`): location stays the network
  service's.
- **The model number** in syscfg: MC349 (16 GB; MC496 32 GB, MC497 64 GB) against the Wi-Fi model's MB292.
  It is identity, not a switch: nothing seen keys the radio off it.
- **No voice.** The iPad 3G had cellular data, and SMS only as the carrier's provisioning channel; there is no
  Phone app on the iPad. CommCenter runs as on the 3GS (mux, SIM, registration, PDP data); a call the panel
  places rings nowhere.
- **What iOS shows.** The rootfs has `Carrier Bundles/iPad/00101` (CarrierLab, as the iPhones' test-PLMN
  bundle), so the status bar shows the operator name and 3G, and Settings gets Carrier and Cellular Data
  (Cellular Data, Data Roaming, APN Settings, SIM PIN). Packet data counts as international roaming on the
  test PLMN, as on the 3GS (`docs/baseband/commcenter-4.2.1-3gs.md`): a freshly prepared 3G iPad came up
  with Data Roaming off, and data flowed once it was turned on.

## The model

`hw/arm/ipad1.c`: the K48 board carries the 3GS's IFX parameters and `bb_uart = 1`; with `baseband=on` the
`ios-baseband` modem sits behind spi2 as on the N90, the strap reads high (`s5l8930_gpio_set_rest_level`,
which now holds a pin high over the reset defaults too), and uart1's backend is the modem's chardev with a
16-byte FIFO. `hw/misc/ios_baseband.c`: an SPI modem also has the chardev; AT arriving on it is answered
there (`boot_uart`) until the kernel's first SPI transfer. The kboot path is unchanged: the machine leaves
the baseband node matchable and fills `device-imei` itself.

`tests/qtest/ipad1-baseband-test.c` checks the strap (both models, across a reset) and iBoot's exchange on
uart1 polled as iBoot polls it, the nvram block inside its second.
