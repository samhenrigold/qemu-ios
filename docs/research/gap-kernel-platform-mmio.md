# iOS 3.2 (7B367) kernel-side MMIO contract for K48AP/S5L8930 — from disassembly of `$SP/dec/kernelcache.k48.mach`

Method: carved every prelinked kext (load addr/size from `__PRELINK_INFO`), wrapped as ELF, `llvm-objdump --triple=thumbv7` (kernel osfmk/arm low-level code at 0xc005a000-0xc0068000 is ARM mode, disassembled with `--triple=armv7`). Derived listings live in `$SP/kx/<kext>.dis` (VAs = kernel VAs); tools `$SP/kx/{carve,mmio,vcall,kstr,rng}.py`. All addresses below are kernel VAs in the 7B367 kernelcache unless noted. `SP` = `/tmp/scratchpad`. `DT` = `$SP/dec/dt.txt` (arm-io `ranges` maps child 0x0..0x3FFFFFFF → 0x80000000, so DT `reg 0x3f100000` = phys 0xBF100000, `0x07000000` = 0x87000000; dt.txt:102).

Kext load map used (prelink info): AppleARMPlatform 0xc02c8000, AppleSynopsysOTGDevice 0xc0357000, IODARTFamily 0xc035f000, AppleCDMA 0xc044a000, AppleS5L8930XUSB 0xc0480000, AppleS5L8920XARM7M 0xc04d0000, AppleS5L8920XIOPFMI 0xc04e6000, AppleS5L8900XCrypto 0xc0546000, AppleARMPL192VIC 0xc054b000, AppleDisplayPipe 0xc0589000, AppleS5L8930XDART 0xc0592000, AppleS5L8930XUSBPhy 0xc060e000, AppleS5L8920X 0xc062f000, AppleS5L8930X 0xc0640000, AppleM68Buttons 0xc0649000, AppleS5L8720X 0xc064b000, AppleD1815PMU 0xc065d000, AppleS5L8900XSerial 0xc0688000, AppleS5L8920XSHA1 0xc06bc000, AppleAMC_r2 0xc06df000, IOP_S5L8930X_firmware 0xc074a000, AppleUSBDeviceMux 0xc07d5000, AppleCLCD 0xc089f000, AppleS5L8900X 0xc086c000. Kexts have no symbol tables; functions are identified by string refs/vtables.

Register access convention in the Apple platform kexts: registers are read/written through virtual accessors `regRead(this, off)` / `regWrite(this, off, val)` (vtable slots 0x384/0x388 in GPIOIC/VIC/I2C; 0x3f8/0x3fc in the PerformanceController, whose base is `this+0x2e0` = `mapDeviceMemoryWithIndex(0)->getVirtualAddress()`; `$SP/kx/S5L8930X.dis` c064338c/c0643394).

## 1. Timer / clock source / PMGR

### 1.1 Kernel (XNU 1504.2.27 pexpert/arm) timer + interrupt bring-up — `kernel.dis` c01d1104..c01d132a (`pe_arm_map_interrupt_controller`/`pe_arm_init_timer`)
- c01d1104: finds node `name="arm-io"`, saves its `device_type` string (→ 0xc02943e8) and `ranges[1]` (0x80000000, the child→parent offset, → 0xc0294408) (c01d1130-c01d1158).
- c01d11ac: finds `interrupt-controller = "master"` (DT arm-io/vic, dt.txt:118-129), `ml_io_map(reg[0]+0x80000000, reg[1])` = **0xBF200000 size 0x40000** → `gVICBase` @0xc0294410 (c01d1276-c01d129e).
- c01d11c8: finds `device_type = "timer"` (**the pmgr node**, dt.txt:145) → `ml_io_map(0xBF100000, 0x6000)` → `gTimerBase` @0xc0294414 (c01d12a6-c01d12ce).
- c01d11e2: finds `device_type = "cpu-debug-interface"` (dt.txt:161-164, 0xBF701000 size 0x1000) → mapped and stored at `cpu_data+0xf4` (c01d12d6-c01d12f2 → c00636fc). c005cf54 (ARM) only records ID_DFR0/DBGDIDR-derived breakpoint/watchpoint counts in a global; **no MMIO write to 0xBF701000 on the boot path found** (only mapped; back it with RAM).
- Platform match c01d11f8-c01d1272: SoC string must be one of `s5l8920x-io`, `s5l8922x-io`, **`s5l8930x-io`** (dt.txt:101) else no timer init.
- Timer init for s5l89[23]x (c01d1208-c01d123c), with T = gTimerBase:
  - `T+0x2008 = 0x7FFFFFFF` (event-timer count buffer),
  - `T+0x2010 = 3` then `T+0x2010 = 1` (STATE: bit1 MANUALUPDATE latches count, bit0 START),
  - `VIC0+0x0C |= 0x40` (INTSELECT: **IRQ 6 routed as FIQ**), `VIC0+0x10 |= 0x40` (INTENABLE bit 6),
  - registers the FIQ timer table 0xc025da00 with `arm_fiq_timer_install(cpu_data, table, T+0x2000, 3)` (c0064354, ARM).
- FIQ table @0xc025da00 = {c00644e4, c00644fc, c0064528, c0064534} (`$SP/kx/kernarm.dis`):
  - c00644fc `read64`: loop `hi=[T+0x2004]; lo=[T+0x2000]; hi2=[T+0x2004]` until hi==hi2; returns (lo,hi) + cpu_data+0x54/0x58 offset → **mach_absolute_time = 64-bit free-running counter at 0xBF102000/0xBF102004** (via c00643ec / c0065774).
  - c0064534 `set_decrementer(v)`: `cpu_data+0x64 = v; [T+0x2008] = v` — **T+0x2008 is a 32-bit down-count interval**, computed by rtclock as `deadline - now` clamped to ≥ 10 ticks (c006579c: `c00653a0(deadline, now)`, c00657e0; c0065b5c re-arm path c0065bba).
  - c0064528: reads `[T+0x2008]` back.
  - c00644e4 FIQ entry: `[T+0x2010] = 3; [T+0x2010] = 1` (ack + restart with the stale count; the new interval is written afterwards by rtclock through c0064534), sets `cpu_data+0x64 = -1`, then `b 0xc0062610` (fiq dispatch).
  - Model requirement: T+0x2000/0x2004 64-bit counter at timebase rate; T+0x2008 count buffer; T+0x2010 state: write with bit1 → reload counter from T+0x2008 and clear the pending interrupt; bit0 → run; assert **IRQ 6** (VIC0 bit 6, configured as FIQ) when the down-counter expires; hold until the next STATE write. This is the openiBoot "event timer" (`plat-a4/timer.c`, `event.c`) semantics; the second event timer (0xBF10200C/0x2014, IRQ 5) is unused by the kernel.
- Timebase: `pe_identify_machine` c01d132c: `boot_args.version` (halfword @+2) must be 2 else panic "pe_identify_machine: Epoch Mismatch" (c01d1336-c01d133e). For s5l8930x it falls to the default table c01d149e: `timebase = 0x016E3600 = 24 000 000 Hz`, cpu default 0x17D78400 (400 MHz), bus default 0x05F5E100 (100 MHz), then overrides from DT `cpus/cpu0` props `timebase-frequency` (c01d14ba), `bus-frequency`, `memory-frequency`, `peripheral-frequency`, `fixed-frequency`, `clock-frequency` (32- or 64-bit; c01d14c6-c01d15ee) into `gPEClockFrequencyInfo` @0xc027862c (offsets: +0x24 timebase, +0x30 bus, +0x48 cpu, +0x60 peripheral, +0x78 memory, +0x90 fixed). **The kernel never decodes PLL CON registers**; iBoot fills those DT props: iBoot-817 `5ff109f0` writes cpu0 `clock-frequency = clock_get_frequency(0)`, `memory-frequency = cgf(2)`, `bus-frequency = cgf(3)`, `peripheral-frequency = cgf(1)`, `fixed-frequency = cgf(4)`, `timebase-frequency = cgf(5)`, arm-io `usbphy-frequency = cgf(0xe)`, and arm-io `clock-frequencies` = memcpy of iBoot's 55-entry (0x37×4 B) frequency table @0x5ff2a0c8 (`$SP/bootchain/iboot.dis` 5ff10a04-5ff10aee, 5ff113c0-5ff113d4; `clock_get_frequency` 5ff10f80 is a tbb switch id 0..0x10 → table offsets 0→+0x14, 1→+0x18, 2→+0x6c, 3→+0x80, 4→+0x84, 5→+0x0, 6→+0xb0, 7→+0x60, 8→+0x90). So whatever PMGR/PLL model satisfies iBoot's clock init defines what the kernel sees.

### 1.2 `AppleS5L8930XIO::start` (arm-io, `$SP/kx/S5L8930X.dis` c0641328-c0641756)
- Reads `chip-revision` (u32; printed as `(rev>>4)+'A', (rev&0xf)+'0'`, c064137e-c064138a; DT value 0 → "A0").
- Reads `clock-frequencies` (OSData); requires ≥ 0x37 (55) u32 entries (c06413bc-c06413c0), builds 55 clock objects (0x28 B each) with alias names from table 0xc06471a4: indices 0x1c-0x1f "hclk", 0x20-0x23 "pclk"+"hclk", 0x27/0x29/0x2b "hclk"+"pclk", 0x2f-0x33 "nclk" (dumped). Device `clock-ids` (e.g. sgx 0x11c, fmi 0x121, uart 0x122+0x004, i2c0 0x134, pmgr 0x118/0x119, otgphy 0x005; dt.txt) index this table by `id & 0xff` → **clock-ids = index into iBoot's frequency table**, not into device-clocks.
- Named clocks fclk/aclk/hclk/pclk/nclk/usbphyclk (c064145c-c0641494) from gPEClockFrequencyInfo (+0x48 cpu, +0x78 mem, +0x30 bus, +0x60 periph, +0x90 fixed) and DT `usbphy-frequency` (c064149c-c0641512).
- `no-clock-gate`/`no-power-gate` props (c0641556/c064156c) disable gating; otherwise looks up `function-clock_gate` ('clkG') and `function-power_gate` ('pwrG') on pmgr (c064167a-c06416e4, panics "can't find 'function-clock_gate', update Device Tree" c0646238).
- `pio-error` boot-arg only: maps arm-io reg (0xBFC00000, 0x1000) and writes `[+4] = (bus-timeout & 0x7FFFFF) | ([+4] & 0xFF800000) | 0x1000000`, `[+0x1C] = 2 (|1 for AXI)`, registers IRQ 0x77 (c06415a6-c064166e). Not used by default → **0xBFC00000 never touched normally**.
- `function-ddr_its0/1` = GPIO 0x1501/0x1502 (dt.txt:100,104) → optional "DDRTemperature" object.

### 1.3 `AppleS5L8930XPerformanceController` (pmgr,s5l8930x) — start c06441b4-c0645412

DT blob is all zero (dt.txt:144) → nothing written; bridge windows only need to be mappable.
- Start-time register **reads**: `[0x08]` bit31 → flag this+0x15ec (c0644342-c064435a); `[0x84]` & `[0x8c]` bits 28-29 compared (`mperf-dividers` applicability, c0644368-c0644382); all 48 clock-config regs `[0x40..0xFC]` cached at this+0x1600+off and a 64-bit "enabled" mask built from bit31 (c064462a-c064467e); gate regs `[0x1014..0x110C]` (gates 1..0x3F): `(v & 0xF) == 0xF` → bit in 64-bit PS mask at this+0x1610 (c0644680-c06446d2). **Nothing is written at start** (no `wr` calls in f=c06441b4 per `vcall.py`), so gate/clock-config registers must read back whatever iBoot programmed (or sane reset defaults if iBoot is skipped).

## 2. VIC — `AppleARMPL192VIC` (`$SP/kx/PL192VIC.dis`)
- start c054c3ec: reads `InterruptControllerName`, `ipid-mask` (4 words → this+0x74; DT 0x0000000f,0,0,0 → IPI irqs 0..3?? see below), `#vic-cells` (4 → +0x68), `vic-offset` (0 → +0x6c), `vic-stride` (0x10000 → +0x70), maxirq = cells*32 = 128 (+0x78); maps reg (0xBF200000, 0x40000) (c054c508-c054c52e). Register accessor c054c1a4/c054c1b8: `[base + vic_offset + stride*vic + off]`.
- No register writes at start except via base class slot 0x364 (AppleARMInterruptController, not decoded).
- registerInterrupt c054c140: `VIC[irq>>5] + 0x100 + 4*(irq&0x1F) = irq | 0x80000000` (vector = irq number with bit31). enable c054c184: `VIC+0x10 = 1<<(irq&0x1F)`; disable c054c164: `VIC+0x14`; status (`'STAT'` function c054c256-c054c28c): `VIC+0x08` (RAWINTR) bit.
- handleInterrupt c054c07c: `v = [VIC0+0xF00]`; `irq = v & 0x7FFFFFFF`; for i in 1..(irq>>5)-1 read `[VIC_i+0xF00]` (daisy acknowledge); if `ipid-mask` bit set → write `[VIC_(irq>>5)+0x1C] = bit` (SOFTINTCLEAR); dispatch; then write `[VIC_i+0xF00] = 0` for i = irq>>5 down to 0 (end-of-interrupt). IPI ('IPID' function c054c22a-c054c254): `[VIC_(irq>>5)+0x18] = 1<<(irq&0x1F)` (SOFTINT) — cpu0 `interrupts = 0x6f` (dt.txt:81), so IPI = irq 0x6f = VIC3 bit 15. Sleep/wake c054c29e-c054c374 saves/restores `+0x10` and `+0x0C` per VIC and writes `+0xF00 = 0`.
- Requirements: 4 daisy-chained PL192 at 0xBF200000 + n·0x10000, vectored mode where VECTADDR read returns the VICVECTADDRn value of the highest active enabled source (with daisy pass-through so VIC0's read yields VIC1-3 vectors), write to VECTADDR = EOI; SOFTINT/SOFTINTCLEAR; INTSELECT bit 6 of VIC0 must route to FIQ. qemu-ios `hw/intc/pl192.c` (Samsung pl192 with daisy chaining) is the right base (used with 2 instances today).

## 3. GPIO IC — `AppleS5L8930XGPIOIC` (S5L8930X.dis)
- start c0642014: `#interrupt-groups` = 6 (+0x6c; 192 irq slots), `#gpio-ports` = 0x16 → 176 pins (+0x74); maps reg (**0xBFA00000**, 0x1000) (c06420c4-c06420ee); reads all 176 per-pin config regs `[4*pin]` and caches low 16 bits (c06420f2-c064210c); for each group g: `[0x800+4g] = 0xFFFFFFFF`, `[0x880+4g] = 0xFFFFFFFF` (c0642116-c0642140); registers the parent IRQ via base class (DT `interrupts = 't'` = **0x74**, dt.txt:132).
- Register map: `0x000-0x2BC` per-pin 32-bit config (16 bits used); `0x800+4g` interrupt **enable** (read = current mask, write 1 = enable; used on wake restore: write saved mask), `0x840+4g` interrupt **disable** (wake writes `~saved`), `0x880+4g` interrupt **status, write-1-to-clear**, `0xC00` group summary (bit g set if any pending in group g). Handler c0642394: loop `s=[0xC00]`; g = highest set bit; `st=[0x880+4g]`; p = highest set bit; pin = 32g+p; if cached cfg `&0xC != 4` (edge) clear status **before** the handler else **after** (c06423ec-c0642460). Wake path c0641dee-c0641e4c rewrites all pin configs.
- Pin config bits (c0642474 registerInterrupt, c0642520 setPinMode): bits1-3 interrupt type: 4 = level-high, 6 = level-low, 8 = edge-rising, 0xA = edge-falling, 0xC = both/autoflip (from DT `interrupts` cell 2: bit0 level, bit1 low/falling, bit2 both); `0x200` = interrupt enable; function/output modes from tbb table c0642546: masks/values 0x260/0x240, 0x260/0x260, 0x6E/0x61|..., 0x26E/(0x200|..), 0x220/0x260 (input/output/alt functions; bit0 = data). Buttons (dt.txt:1022-1033): menu=pin0x00, hold=0x01, volup=0x02, voldown=0x03, ringerab=0x04, all registered as type 7/5 (both edges, 0xC); `AppleM68Buttons` (c064a32e-c064a440) just resolves `function-button_<name>` (GPIO read, cell `0` = polarity) and `function-wake_button_<name>` (PMU 'STAT' 0x180/0x181). Model: reads of pin regs 0x00-0x10 must return bit0 = current button level; asserting a button = flip bit0 + set `0x880` bit + `0xC00` bit 0 + raise IRQ 0x74.
- PMU IRQ line = GPIO pin 0x0D, type 1 (level) (dt.txt:551); multitouch 0x15 (dt.txt:378); TCA6408 0x11.

## 4. PMU (Dialog D1815 @ I2C0 addr 0x74) and the I2C controller

### 4.1 `AppleD1815PMU` I2C register traffic (`$SP/kx/D1815PMU.dis`; `_writeRegs`=c065f1cc(this, reg, buf, n), `_readRegs`=c065f2e8; nub slave address from DT `reg = 0x74` dt.txt:548)

(c0660f00-c0660f0e writes reg 0x81, 1 byte, value 0x30... then 0x01), RTC read c065f558: `rd 0x81, 0x83, 0x82 (lo nibble & hi nibble), 0x80` → RTC counter bytes; registers GPIO IRQ pin 0x0D.
- IRQ handler c06602ec: `rd 0x01 (6)` = event regs A-F (clear-on-read), dispatches child handlers per event bit (dock/charger/mikey); wake path c06603f8+: event A (0x01) bit0 menu, bit1 hold, bit2 ringerab, bit3 usb, bit4 firewire, bit5 acc; event B (0x02) bit3 chg_end; "rtc" from this+0x8b bit0 (event E?); 'STAT' function reads `0x07 (5)` power-status (c065f3a8) — used by USB/charger detection (`function-usb_det` = charger STAT 0x80).
- Shutdown/standby c065f768: `wr 0x68=0`, `rd 0x01(6)`, `wr 0x0C(6) = C6 70 0F FA EF CC`, `wr 0x81=0`, `rd 0x07(5)`, chargetrap → `wr 0x8F = 0x10` (else 0x90), standby: `rd 0x12; wr 0x12 |= 1` (OOC shutdown) then spin; reboot: returns to AppleARMWatchDogTimer → PMGR WDTr.
- ADC c0661300: `wr 0x30` (mux/start), `rd 0x31 (2)`; timeout string "_timeoutADC event=%02x mask=%02x adc=%02x" — the ADC completion is expected as a PMU event (event bit) → model can return the result immediately and raise no IRQ only if the driver polls; **polling vs IRQ for ADC NOT confirmed** (safest: set the ADC-done event bit and pulse the GPIO 0x0D line).
- Backlight c065f214/c065f258: `wr 0x66, 0x67, 0x68` (but DT `no-backlight` on pmu (dt.txt:556) → `AppleD1815PMUBacklight::start: not loading backlight driver`; iPad backlight is SWI/PWM-based via `function-backlight_*`). Watchdog `AppleD1815PMUWatchDogTimer` needs `function-keepact` (GPIO 0x203, dt.txt:565) else "hardware watchdog inactive".
- Minimal I2C slave model: 256 registers RAM-backed; reg 0x01-0x06 clear-on-read; keep 0x07 status = external power present bits as desired; reg 0x50-0x59 GPIO; RTC 0x80-0x83 counting seconds. RTC epoch/format: **NOT decoded** (c065f5d8+ composes the value; D1815 datasheet not available).

### 4.2 I2C controller `AppleS5L8920XI2CController` (matches `i2c,s5l8920x`; `$SP/kx/S5L8920X.dis`; base this+0x74 = map(reg 0x83200000/0x83300000/0x83400000, 0x1000); accessor slots 0x384/0x388 c0635860/c0635868)
- enable c06357b4: clock gate on (provider slot 0x360), `[0x0C] = 0x37` (clear status), `[0x08] = 0xF0`; disable: `[0x08] = 0`.
- transfer c063592c (one message with sub-address): `[0x00] = slave address (DT reg value 0x74 as stored, this+0xa0)`, `[0x10] = subaddress byte`, `[0x18] = data length` (≤ 0x80), for writes push bytes to `[0x20]` FIFO, then `[0x24] = (isWrite ? 1 : 0) | 4` (bit2 = start) (c063598c-c0635a7e); waits for the interrupt (or polls slot 0x380 in the no-interrupt path c0635ade).
- interruptFilter c0635888: `s = [0x0C]`; `s & 0x20` → error/NACK (kIOReturn 0xe00002e9); `s & 0x10` → done: for reads pop `len` bytes from `[0x20]`; other bits → "unexpected interrupt status"; ack by writing `s` back to `[0x0C]`. IRQs: i2c0 0x13, i2c2 0x15 (dt.txt:544,648).
- Same layout as openiBoot `plat-a4/i2c.c` (0x00 addr, 0x08 init 0x30, 0x0C status bit5 error, 0x10 subreg, 0x18 count, 0x20 FIFO, 0x24 cmd bit0 write/bit2 start) and iEmu `s5l8930_i2c.c`; the S5L8720 IICCON model in qemu-ios is **not** reusable.

## 5. CDMA / DMA-AES (`AppleCDMA`, `$SP/kx/CDMA.dis`; base this+0x58 = map(0x87000000,0x26000), AES this+0x5c = map(0x87800000,0x9000); `cdma-version = 2`, dt.txt:167)
- start c044b2fc-c044b3ae: channel enable/disable c044b02c (v2): enable ch → `[base + 4*(ch>>5)] = 1<<(ch&0x1F)` (**+0x00/+0x04 = channel-set**), disable → `[base + 8 + 4*(ch>>5)]` (**+0x08/+0x0C = channel-clear**); at start enables ch 0 and disables ch 1..0x25; per-device channels come from DT `dma-channels` (id, fifo phys, {burst,width}, filter ctx) e.g. clcd `0x25, 0x8910103C, 0x00080004, 1`, i2s0 `0x1A/0x1B`, amc 0x17, sha1 4, sdio 3 (dt.txt:932,722,1001,260,246); IRQs `0x31..` from cdma `interrupts` (0x31 + ch).
- Per-channel regs at `base + (ch<<12)` (c044c46c, c044c7e4, c044d014): `+0x00` control/status — start = `(ctrl & ~0x21) | 1` masked with `~(ctrl & 0x180000)` (c044c90c-c044c92a); running = `(status & 0x30000) == 0x10000` (c044c85a-c044c86a, v2 checks `0x230000`); abort: `|= 4`, poll `& 0x200000`, then write 2 (clear) (c044c482-c044ca0); `|= 0x18` / `|= 0x24` / `|= 0x20` stop variants; init writes `0x88 | (aes_filter_ctx << 8)` (c044d054-c044d066) and `+0x14 = descriptor chain phys` (c044d052); `+0x0C` and `+0x10` read (remaining bytes / current address), `+0x14` current descriptor. Descriptor = 32 B `{next, flags(&0xF: 3 = data, 0x100 last), addr, len, iv[4]}` (c044c4ce-c044c51e) — identical to openiBoot `plat-a4/cdma.c:14-20, 219-298`.
- AES engine: `CDMAAES` (IOAESAccelerator subclass) only touches AES ctx0 `+0x00`: key-disabled bits read `(v >> keyid) & 1` and written `1 << keyid` (`function-disable_keys` / `_mapKeyID`, c044b014-c044b02a; keys 0 = UID, 1 = GID per "key %d/%d not enabled"). AES data ops are done by attaching the filter context to a DMA channel (setup/IV/key at `0x87800000 + ctx<<12` as in openiBoot `dma.h:21-29`). **Boot-path use besides NAND**: `IOAESAccelerator` user clients (SecureRoot/keybag via `AppleKeyStore` in userland — uses UID key), FairPlay; `AppleS5L8900XAES` does not match on K48 (no `aes,s5l8900x` node), `AppleS5L8900XPKE` matches `pke,s5l8920x` (0x83100000, IRQ 0x12) for RSA (AMFI trust-cache/keybag), `AppleS5L8920XSHA1` matches `sha1,s5l8920x` (0x80100000: `+0x04 = 1` reset, `+0x10 = mode/len`, data via CDMA ch 4 to FIFO 0x801000A0, `+0x00` start, digest read big-endian from `+0x20..+0x30`; c06bd5ee-c06bd6b6, c06bd4fc-c06bd538). Exact AES-DMA descriptor flags for IV/key segments were not re-derived (openiBoot `cdma.c:343-393` applies).

## 6. USB
- `AppleS5L8930XUSBPhy` (`otgphyctrl,s5l8930x` 0x86000000 size 0x1000; `$SP/kx/USBPhy.dis`, base this+0x54): powerUp c060f750: gates on (slots 0x364/0x360), `[0x00] = ref-clock-sel << 1` (DT 3 → 6), `[0x04] = usbphyclk code (this+0x68)`, HSIC only: `[0x60]=0x200|0x1E0, [0x64]|=2`; PHY reset c060f224: `[0x08]=1`, 20 µs, `[0x08]=0`, 1 ms (link reset c060f248 uses value 2). enableDeviceMode c060f680: `[0x44] = phy-tuning-val (0)`, reset, `[0x1C] |= 2` (device) / `&= ~2`. powerDown: `[0x00] = 0x11`. Charger detect ('DMON'): `[0x48] = (v & ~6) | mode<<1`. No reads with side effects → RAM-backed 0x68-byte register file suffices; same offsets as S5L8720 OPHYPWR/OPHYCLK/ORSTCON/0x1C/0x44 → qemu-ios `ipod_touch_usb_phys.c` reusable at the new base.
- `AppleSynopsysOTGDevice` (usb-device 0x86100000 size 0x10000, IRQ 0xD, `clock-idx 0`): register offsets used (mmio scan of `$SP/kx/OTGDevice.dis`, base this+0x118): 0x00, 0x08, 0x0C, 0x10, 0x14, 0x18, 0x24, 0x28, 0x2C, 0x44, 0x48, 0x50, 0x104/0x108/0x118 (DPTXFSIZn), 0x440, 0x800, 0x804, 0x808, 0x810, 0x814, 0x818, 0x81C, 0x820, 0x824, 0x830, 0x834, 0x900+n*0x20 (DIEPCTL/INT/TSIZ/DMA), 0x9D0/0x9D4, 0xB00+n*0x20 (DOEP*) — **pure standard DWC-OTG device-mode set, identical to the S5L8720 core** → qemu-ios `ipod_touch_usb_otg.c` reusable (new base/IRQ; `need-ahb-bridge-flushing`, `ForceFullSpeed` optional props). Core init needs GRSTCTL AHBIDLE/CSRST semantics ("unable to reset core", "AHB not idle").
- `AppleS5L8930XUSBArbitrator` (usb-complex 0xBF108000): maps the reg (this+0x7c) but only writes the USB_CTL register when `hsic-enabled` is present (c04816a4-c04816d0 → c04812f0); K48 DT has no `hsic-enabled` → **0xBF108000 must only be mappable**. `AppleEmbeddedUSBArbitrator` publishes the device nub on cable-type change via the PMU/charger `function-usb_det` (D1815 STAT bit 0x80) or `force-usb-host`/`no-pmu`; usb-device `cable-type = 1` (dt.txt:798). - `AppleUSBDeviceMux` (`USBDeviceFunction = AppleUSBMux`, 3.2 protocol version negotiation "Version packet", TCP-over-bulk) is unchanged from the iPod touch 2G stack, so the existing libimobiledevice/usbmuxd bridging (`ipod_touch_tcp_usb.c`) transfers once the OTG model enumerates.

## 7. Other devices on the boot path
- **SWI** (`AppleS5L8720XSWI`, matches 2nd compatible `swi,s5l8720x`, 0xBF600000; `$SP/kx/S5L8720X.dis` base this+0x58): start c064efc0: `[0x24] = str-delay-derived period`, `[0x00] = ((nclk-div-1) << 8) | 3`, `[0x0C] |= ...` (c064f1ae); command c064e7e8: immediate form `[0x20] = cmd; [0x1C] = 3`; queued form: **poll `[0x14] & 1 == 0`**, `[0x18] = cmd; [0x14] = 3`. Provides `corV` (core voltage for DPSM) and backlight (`function-backlight_*`); model: bit0 of +0x14 must self-clear.
- **DART** (`AppleS5L8930XDART` @0x88D00000/0x89D00000 size 0x2000; base this+0x508): start writes `[0x10] = 0x3F`, `[0x18] = invalid-translation-target (0xBF109000, dt.txt:180) | 0x400 when translation disabled`, `[0x0C] = per-SID config (0x80 per byte for no-fault clients)`, `[0x1000] = 0x7FFFFFFF`, `[0x1004..0x100C] = 0` (c05941e6-c0594336); STE programming c0593588: for sid 0..3, idx 0..0x3F: `[0x08] = STE; [0x00] = 5 | (sid<<8) | (idx<<22)` then `_dartWaitOpReady`: poll `[0x00] & 8 == 0` up to 1000×1 µs else panic "DART: busy timeout" (c05934d0-c0593522); fault path reads `[0x14]`,`[0x18]`,`[0x1000]`. Clients: dart2 `mapper-clcd/rgbout/scaler`, dart1 `isp/jpeg/venc`. `IOMobileGraphicsFamily` uses `iommu-parent` to get a mapper and prints "no mapper on this platform" if absent (c0572fe4/c0572ff4); `IOSurfaceRoot` checks arm-io `iommu-present` (c061835c). **Implication**: with the stock DT, AppleCLCD/AppleDisplayPipe framebuffer addresses are DART IOVAs → either implement DART page-table translation for display DMA (STE→PTE walk; PTE format not decoded) or strip `iommu-present`/`iommu-parent` from the injected DT so the display stack falls back to physical addresses (untested mitigation).
- **CLCD** (0x89200000, base this+0x1aa4): soft reset `[0x00] = 0x300` then poll `[0x00] & 0x100` cleared within 10×1 ms ("did not complete soft reset in 10 msecs", c08a2fd0-c08a2fee); `[0x50]` bit1 must read 1 when the controller is stopped (ENVID_F_READY_DOWN wait, c08a3110-c08a312c); timing regs 0x54-0x60, 0x64/0x68, gamma 0x34/0x38 (write) / 0x3C (read), MIE 0x240-0x248, 0x08/0x0C/0x14/0x18/0x2C. **DisplayPipe** (0x89000000, base this+0x254): regs 0x101C, 0x1028, 0x102C, 0x1030-0x103C, 0x1044 (param-FIFO count, must read 0 after flush), 0x1048-0x1054, 0x105C, 0x2040/0x2044/0x205C-0x2064 (blend), 0x307C/0x3080, 0x3D00/0x3D14 (int enable/status), 0x4040-0x4048 (UI0 fmt/addr/stride), 0x5040-0x5050 (UI1) — consistent with openiBoot `plat-a4/clcd.c:260-274,723-733`. MIPI-DSIM 0x89500000 (`AppleS5L8720XMIPIDSIController`, same IP as 8720 → reuse `ipod_touch_mipi_dsi.c`), panel `lcd,pinot` via `ApplePinotLCD`.
- **AMC** (`amc,s5l8920x` 0x84100000/0x84000000/0x84300000, DMA ch 0x17): 438 KB kext; start uses register helper functions with completion polling ("Failed to set stall source", "Memory configuration read failed", c06e5720-c06e5790); **not decoded**. Audio only; SpringBoard does not need it, but a hang in its start would block IOKit matching — treat as RAM-backed first and verify.
- **IOP** (must-have for NAND, see `$SP/research/ref-nand-stack.md` §0 and `ref-iemu.md` §2): kernel `AppleS5L8920XARM7M` maps `iop` reg[0] 0x86300000 (this+0x60) and reg[1] 0xBF300000 (IOP VIC, this+0x68) (c04d2d42-c04d2d72, "mapped I/O registers at %p/0x%08x, %p/0x%08x"), and touches control regs `+0x100` (read/write, start/stop bits), `+0x110`, `+0x114`, `+0x118` (entry/args) (mmio scan of `$SP/kx/ARM7M.dis`), consistent with iEmu's 0x100/0x110 model; NAND/SDIO traffic then goes over the message ring in shared memory (opcodes not decoded here).
- **UART** (`uart,s5l8900x`): Samsung layout (UTRSTAT 0x10, UTXH 0x20, UBAUD 0x28, UDIVSLOT 0x2C, UFSTAT 0x18…) as in qemu-ios; uart0 0x82500000 IRQ 0x16 `boot-console`.
- **AMFI/sandbox**: no hardware dependencies beyond PKE/SHA1 accelerators (`IOPKEAccelerator` "doPowerMod" in AMFI c03b8f6c); boot-args `amfi_get_out_of_my_way`, `amfi_allow_any_signature`, `amfi_unrestrict_task_for_pid` (c03b9650-c03b9720).

- What 'PRFA' perf-advise writes beyond the generic DPSM transition; the DPSM register block 0x100-0x13F field meanings.
- DART PTE/STE bit layout (only the register protocol), AMC register map, AppleS5L8920XPWM register use, AppleARMInterruptController base-class init (VIC vtable slot 0x364), the IOPFMI/IOP message-ring opcodes and struct layout, CDMA global interrupt-status register (interrupts are per-channel IRQ lines 0x31+ch; no global status read was found in the kernel driver), the AES-DMA IV/key descriptor flags in the kernel driver (openiBoot values assumed), and the multitouch SPI/Z2 protocol.
