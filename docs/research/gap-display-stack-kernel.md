## 1. Kernel-side register contract

### 1.1 AppleDisplayPipe (DISPLAY_PIPE0 @0x89000000, 7 KiB window, `fRegisters` = this+0x254)

Class chain: AppleCLCD : AppleDisplayPipe : IOMobileFramebuffer (AppleCLCD::start_hardware calls `super::start_hardware` through AppleDisplayPipe vtable 0xc058f9c8 slot 0x358, `CLCD.dis` c08a2cdc-c08a2cf2; DisplayPipe vtable slot 0x3d0/0x460 etc. resolve into IOMobileGraphics).

Start (`AppleDisplayPipe::start_hardware` c058b294, `DisplayPipe.dis`):
- maps reg index 0 (`mapDeviceMemoryWithIndex(0,0x100)` vt 0x208, c058b31a) → fRegisters at this+0x254 (c058b346); register-cache allocs 0x60/0x68/0x7c/0x7c/0xd44 bytes (general/blend/UI0/UI1/video, c058b2c8-c058b2ec).
- IOFilterInterruptEventSource on provider IRQ **index 0 = 0x2a** (c058b370, filter=c058ba20, action=c058b5dc; PMFs at __const c058fe38/c058fe40).
- If main display (this+0x236, set to 1 by AppleCLCD at c08a2cc2): **adopts iBoot's scanout by reading hardware**: writes DP[0x2064]=0x800003ff (underrun color, c058b408); reads DP[0x1038], bit8 → UI0 live: stride = DP[0x4048]&~0x3f → this+0x238; fmt = (DP[0x4040]>>8)&7 → +0x240; **fb base = DP[0x4044]** → +0x23c; width = ((DP[0x4060]>>16)&0x7ff)-((DP[0x4050]>>16)&0x7ff) → +0x64; height = (DP[0x4060]&0x7ff)-(DP[0x4050]&0x7ff) → +0x68 (c058b410-c058b4ac; bit9 → same from 0x5040.. for UI1). It never reads DT `vram`; the console FB comes from boot_args video struct (xnu `video_console.c` "initialize_screen: Strange framebuffer", `kernel.strva` c01e7db8).
- Writes DP[0x105c]=0x13880801, DP[0x1054]=1, DP[0x205c]= 0x018001f0 (vt0x3d0 true) or 0x01c001f0 (c058b4ae-c058b4e0; openiBoot clcd.c:271 writes `(0x180<<16)|0x1F0` for PIPE0).
- If a DART mapper exists (this+0x220): `fMapper->callPlatformFunction("makeTransitionMapping", page=fb>>12, npages=(stride*height>>12)+2)` (c058b4fc-c058b51e) — i.e. an identity IOVA→PA window is installed for iBoot's framebuffer so the value in DP[0x4044] keeps working once translation is on. It is torn down on the first kernel-driven frame via "clearTransitionMapping" (c058b6b4-c058b6ce). **Conclusion: the pipe address registers hold DART IOVAs when `iommu-parent` is present.**
- Wraps iBoot's FB as an IOSurface (c058ad10): pixel format `'ARGB'` (0x42475241) if fmt≤1 else `'L565'` (0x4c353635), bpe 4/2, width/height/stride from above, allocSize=(stride*height+0xfff)&~0xfff, `IOSurfaceIsGlobal`, `PurpleGfxMem` region; if no mapper → `IOMemoryDescriptor::withPhysicalAddress(fb,size,dirOut)` (c058adda-c058ade6).
- `display-default-color` DT prop → this+0x1a98, else 0xffffffff (c058b534-c058b570).

**Register programming is done through a parameter FIFO, not direct stores** (c058a9a0 "DPCPFDMA"): 
- DP[0x1044] = FIFO fill count (polled to 0; "Wait for FIFO to drain", DP[0x101c]&0xf0==0x20 sanity, DP[0x1050]=1 forces a flush, c058aa2a-c058aae2).
- Header word to **DP[0x103c]** = 0x80000000 | (nwords<<16 & 0x03ff0000) | (bit29 if program_hardware's bool arg) | swapID(16 bit) (c058aaf4-c058ab26); then per packet: (count<<16)|reg_offset (c058ab2a-c058ab44), then `count` data words (c058ab4e-c058ab5c); ≤0x3fe words total, ≤0x1f4 packets (c058a886). DP[0x1034] = swapID-1 written when arg3 set (c058ab84-c058ab88). Hardware applies the writes at the next frame; the `dma-channels ch 0x25 @0x8910103C` in the clcd node is the CDMA descriptor for this FIFO port (+0x103C) — note the DT points clcd at PIPE1's port and rgbout at PIPE0's (0x8900103C, l.980); the kernel driver never uses CDMA for it (all writes are CPU `str` to fRegisters+0x103c), so the emulator only needs the MMIO port.
- DP[0x104c] "DPCPFDMA" config: kernel forces bit4 (auto mode), &~0x500 |0x200, &~0x3f80000, &~0x70000, |0x4000000 (c058c168-c058c1a2); power-up writes 0x04000210 (c058c004).

Per-layer window packets (program_hardware c058c074, layer L: base 0x4044+L*0x1000; UI0=0x4044, UI1=0x5044; video block 0x3000):
- 0x4040 fmt: bits 8-10 = 0 for 'BGRA'/'ARGB', 2 for '4444', 4 otherwise (c058c5e2-0x30c61c); 0x4044 = **surface device address** (swap->surface[i]+0xa4, DART IOVA; c058c642); 0x4048 = (bytesPerRow << interlaceShift) &~0x3f | 0x2 (tiled: |height<<4) (c058c54e-c058c5de, c058c64e); 0x404c = 1 if src rect empty (c058c65c); 0x4050 = dst pos (x<<16|y) (c058c66a); 0x4054 = src pos, 0x4064 = src end (c058c51e/c058c52c); 0x4060 = dst end (x+w)<<16|(y+h) (c058c676). Disabled layer: all of 0x4044/48/4c/50/60 = 0 (c058c242-c058c278). Alignment asserts: linear stride %64, tiled %256, min 32x16, "Can't scale in H3" (`DisplayPipe.dis` strings c058f130..c058f21c).
- Blend 0x2040 (UI0)/0x2048 (UI1)/0x2044 (video): per-layer alpha/enable word ((cfg&~0x300)|..., 0xff0000 alpha, bits 0-1) (c058c27c-c058c2c2); 0x1038 = layer enable mask bit8 UI0, bit9 UI1, bit10 video (c058d828, c058d83a).
- After packets: `c058a9a0(this, bool, &fifoList, 1)` commits; then three extra packets via c058abf8 (ping-pong of UI base addr 0x4044/0x5044 for swapID+1..+3, c058d91c-c058d964).

Interrupts (filter c058ba20, handler c058b5dc):
- **DP[0x102c] = IRQ status, write-1-to-clear**; **DP[0x1028] = IRQ enable** (shadow this+0x258). Filter: st=DP[0x102c]; fIntStatus=st; pend=st&en; if pend {DP[0x102c]=pend; return true} else {DP[0x102c]=st; return false} (c058ba30-c058ba78).
- Bits: 0x1 frame/VBL done (main path: vt0x460 swap-complete, compares this+0x1a94 (expected swapID) with **DP[0x1048]&0xffff = last completed swap ID** (c058b692-c058b6a0), then DP[0x102c]=0x100 ack after `tst 0x100` (c058b674-c058b680), calls IOMobileFramebuffer swap-done 0xc05708ed); 0x2 underrun (logs DP[0x1038],0x4044,0x5044,0x307c,0x3080; "Num of Underruns"); 0x8 packet miss; 0x40 bad packet; 0x200 frame read error (c058b82a-c058b9e6). Enable of bit0 (DP[0x1028]=1) happens when a swap is queued (c058b05a-c058b068, c058b0b4-c058b0c2). Disable path: DP[0x1028]=0, DP[0x102c]=0xffffffff (c058b13a-c058b152).
- DP[0x101c] bit 0x10000000 checked in handler (c058b6f6-c058b6fc); bits 0xf0==0x20 in FIFO wait.
Power: save regs 0x102c,0x1030,0x104c,0x1054,0x105c,0x205c,0x2060 (c058ba8c-c058bac2); power-up (c058bf68): IOMFB DART power (0xc0570121), DP[0x102c]=~0, **DP[0x1030]=(w&0x7ff)<<16 | (h>>interlace)&0x7ff** (c058bf84-c058bfa4), DP[0x2040/44/48]=0, DP[0x1050]=1, DP[0x104c]=0x04000210, DP[0x105c]=0x13880801, DP[0x1054]=1, DP[0x205c]. Stop (c058b0c8): blend regs=0, DP[0x1038]=0, IOSleep(20). printDPRegs dumps 0x1000 (0x18 words), 0x2000 (0x1a), 0x3000 (0x351), 0x4000/0x5000 (0x1f) (c058a5bc-c058a62a).

### 1.3 MIPI-DSIM (0x89500000; AppleS5L8720XMIPIDSIController in AppleS5L8720X kext, base = this+0x58)
Same Samsung DSIM layout and **same kext as iPod touch 2G**, so `hw/arm/ipod_touch_mipi_dsi.c` is reusable. Start (c064e4ec): maps reg 0, `#lanes`→+0xb8; **adopts iBoot state by reading regs 0x00..0x58** via vt0x368 (c064e588-c064e5ae); CONFIG(0x10): lanes=((>>5)&3)+1, lane-enable=(>>1)&0xf; PLLCTRL(0x4c) bit23 = PLL on; STATUS(0x00) bit8 → skips extra clock enable. Enable sequence (c064e0e0): SWRST(0x04)=1 then **poll STATUS bit 0x100000 (PLL stable)**; CLKCTRL(0x08)/PLLCTRL/PLLTMR(0x50)/PHYACCHR(0x54,0x58)/MDRESOL(0x18)/MVPORCH(0x1c)/MHPORCH(0x20)/MSYNC(0x24)/SDRESOL(0x28) from saved values; FIFOCTRL(0x44)=0x1f, FIFOTHLD(0x40)=0x1ff; ESCMODE(0x14)=0x00100080/0x80/0x8a/0x8f with polls of STATUS: `(lanes&0xf)|0x100` set (stop state), `(lanes<<4)|0x200` set/clear (ULPS), bit 0x400 (HS clk ready, c064df5c after CLKCTRL bit31). Short packet send vt0x354 (c064e09c): PKTHDR(0x34)=(type&0x3f)|d0<<8|d1<<16, IODelay(1), **poll STATUS bit0**. Long packet vt0x358 (c064dfbc): PAYLOAD(0x38) words then header. **The kernel never reads RXFIFO(0x3c)** (no DCS reads); the panel-ID read is iBoot-only.

### 1.4 ApplePinotLCD (`lcd,pinot`, PinotLCD.dis)
start (c088a27c): provider = DSI controller; **reads `lcd-panel-id` from the lcd DT node; if the value is 0 → start() returns false** (c088a2de-c088a2e2); needs `function-lcd_ldo`/`function-reset`; registers with DSI (vt0x214), publishes `ApplePinotLCDErrorCount`. `_lcdEnable` (c088a098): ldo on, IOSleep 10, dsi vt0x350(1), reset(0), IOSleep 6, vt0x354, IODelay 10, dsi vt0x354(1), IOSleep 25, callback, IODelay 100, DCS 0x11 sleep-out (vt0x358 type 5), IOSleep 102, DCS 0x29 display-on, IOSleep 102+17. Off: 0x28/0x10. **Garbage but nonzero panel ID: harmless (no table lookup). Zero/failed read: ApplePinotLCD absent → AppleCLCD logs "Couldn't allocate AppleARMFunction for function-lcd_enable" and continues; display still scans.** iBoot (`iboot.dis` 5ff05c80-5ff05e20 pinot_init): uses NVRAM env `pinot-panel-id` if set, else DSIM generic read type 0x14 param 0xB1 (5ff05d0a-5ff05d1c), requires long-read response 0x1a/0x1c with len>2 (5ff0860e-5ff08616, 5ff05d24), packs bytes into `lcd-panel-id`/`raw-panel-id`/`display-default-color`/`display-backlight-calibration` DT props (5ff05ba0-5ff05bde); on failure prints "read of pinot panel id failed" and continues with id 0. The existing model's reply (header 0xb114 → 0x1a|3<<8, 0x00a1d13c) satisfies it.

### 1.6 DART (AppleS5L8930XDART, dart2 @0x89d00000, regs = this+0x508; `DART.dis`)
- +0x00 TLB_OP: bit3 busy (wait ≤1000×1ms "DART: busy timeout" c05934fe-c059351a). Ops: read STE = (seg<<22)|(sid<<8)|0x4 then read +0x08 (c0593684-c05936a2); write STE: +0x08=val, TLB_OP=(seg<<22)|(sid<<8)|0x5 (c0593704-c059371e); invalidate TLB: 0x2|(sidmask<<8)|(flidmask<<12) (c0593e66-c0593e7c); clear all: 0xff02 (c0593574).
- +0x0c CONFIG: translation enable per SID = 0x80<<(sid*8) (c0593ece-c0593f0a); +0x10 ERROR_STATUS (W1C 0x3f, decode "STE invalid/PTE invalid/write protect/no execute/AXI slave error/decode"); +0x14 ERROR_ADDRESS; +0x18 DIAG_CONFIG (bit 0x400 toggled on disable); +0x1000 PERF_CONFIG, +0x1004/8/c TLB miss/wait/hit.
- Address split (c0593906-c059391e, c0593110-c0593146): FLID = VA[31:28], SEG = VA[27:22] (64 STEs/SID), PTE index = VA[21:12] (1024 4-byte PTEs per 4 KiB table). **PTE = (PA & ~0xfff) | 1 (valid)** (c0593244-c059324e), flags byte OR'd for variant (c0593264). STE = page-table PA (validity shown by printRegs). Shadow STE array at this+0xe8+sid*0x100. `invalid-translation-target`=0xbf109000, `defer-translation-clients`=1 → SID0 (clcd) translation enabled only when IOMFB asks (`setActive`/`powerUpDART_gated`).
- IOSurfaceRoot checks arm-io `iommu-present` and "has io-mmu set but cannot find DART instance" (IOSurface.dis strings c061835c-c06183c4). IOMobileFramebuffer::start (c0571cf2-c0571d26): `use-legacy-DART` → skip; else `iommu-parent` → IOMapper for device; absent → "no mapper on this platform" and continues with **physical addresses** (IODMACommand pool of 30, 32-bit, c0571d5a-c0571d98).
- **Emulator choice**: (a) model dart2 (STE/PTE walk on every pipe fetch, ~150 lines) or (b) strip `iommu-parent` from the clcd node (and `iommu-present`? no—only affects IOSurfaceRoot warning) so IOMFB/DisplayPipe use PAs; with (b) dart2 still probes: keep TLB_OP busy bit always 0 and regs as RAM. NOT found: the IOVA window base/size chosen by IODARTVMSpace::forMapper for mapper-clcd (IODART.dis not traced).

## 2. Does the kernel display path need SGX or DART?
- IOSurface allocation: no SGX involvement; `IOSurfaceRoot` uses memory regions `PurpleGfxMem`/`PurpleEDRAM` (IOSurface.dis c061836c/c0618384) and a DART broker only when `iommu-present` (warning only if none). IOMobileFramebuffer needs `IOCoreSurfaceRoot` (c0571c4e), a mapper only if `iommu-parent`. No `IOAcceleratorES` reference in IOMobileGraphics/DisplayPipe/CLCD strings (checked `kstr.py`).
- DART: needed only because clcd node has `iommu-parent` (see 1.6).
- M2 scaler: not required by the kernel swap path; required by userland only when QuartzCore chooses `IOSurfaceAcceleratorTransferSurfaceWithSwap` (see 3).
- SGX: `sgx` DT node exists → IMGSGX535 (`SGXDriver`, match `sgx,s5l8920x`) will start against 0x85100000; on failure it logs "SGX: Microkernel unresponsive" and returns error (c0693df2 path branches to c0693fb0, no panic call) → no `IOAcceleratorES`. Safer: delete the sgx node (or model a dead SGX that fails the microkernel handshake quickly to avoid multi-second timeouts).

## 3. Userland 3.2 path (GPU-less)
- SpringBoard 3.2 (`$SP/dec/SpringBoard`): links only CoreSurface/GraphicsServices/IOMobileFramebuffer/IOSurface — **no OpenGLES/EAGL/PVR references at all**; only `IOMobileFramebufferOpen`, `SetDebugFlags`, `IOSurfaceGetBaseAddress` (snapshots). No hard SGX dependency.
- QuartzCore (cache 0x30951000): `CADisplayIOMFB` opens IOMFB (0x309532f0 `IOMobileFramebufferOpen`, `GetLayerDefaultSurface` 0x30953310, env `MBX2D_OFFSCREEN`/`MBX2D_PAGE_FLIP` 0x30953276/8e). Present (0x30961fcc): `SwapBegin`(4) → `SwapSetBackgroundColor` → `SwapSetLayer` ×3 (layers 0..2; layer 0 gets the rendered IOSurface with float src/dst rects, 1-2 cleared) → `SwapEnd`(5) → `SwapWait`(6) ("swap_end returned error %x"). Power/blank (0x30961194) uses the same with zero layers + `RequestPowerChange`. Render surfaces are created with `IOSurfaceCreate{IsGlobal, MemoryRegion, AllocSize, PlaneInfo, BufferTileMode}` (0x30974f06; formats 'ARGB'/'565L'/'f024'). `CA_ENABLE_OGL` decides GL vs software renderer ("image is too large for software renderer"). The final compose step 0x309c9594 calls `IOSurfaceAcceleratorCreate` (0x309c7660) and, if it exists, `IOSurfaceAccelerator[Conditional]TransferSurfaceWithSwap` with a symmetric-transform index (rotation/flip bits, 0x309c95c0-0x309c96d0); **it returns 0 when no accelerator; the CPU fallback in its (vtable) caller was NOT traced**. `display-rotation`/`display-scale` are consumed only by DataMigration (cache scan), not by CA/IOMFB.
- Geometry: pipe/panel is **1024×768 landscape** (openiBoot k48 LCD table clcd.c:72: `{"k48",0xA,0x413B380,0x84,1024,0x85,0x85,0x87,768,0xA,0xA,0xC,…,18,3,0x644}`; DP[0x1030]=(1024<<16)|768); portrait UI (768×1024) is produced by CA (GL or software+scaler/CPU rotate). IOMFB `GetDisplaySize` (sel 8) returns pipe size.
- IOMobileFramebufferUserClient selectors (userland `IOMobileFramebuffer` @0x337ba000, scalar stub 0x337bcbdc, struct stub 0x337bcbec): 1 SwapSurface, 2 WaitSurface, 3 GetLayerDefaultSurface, 4 SwapBegin (out swapID), 5 SwapEnd (struct in **0x8c** bytes at client+0x10; kernel accepts 0x8c/0xd4/0xe4/0xf4 "CLCDTransaction size mismatch" c056f388-c056f3b8), 6 SwapWait, 7 GetID, 8 GetDisplaySize(2 out), 9 VSync notify on/off, 0xa TVOutMode, 0xb WSSInfo, 0xc RequestPowerChange, 0xd EnableStatistics, 0xe SetFlags, 0xf SetDebugFlags, 0x10 TVOutSignalType, 0x11 SetGammaTable(struct), 0x12 IsMainDisplay, 0x13 WhiteOnBlack, 0x14 SwapSignal, 0x15 HotPlug notify, 0x16 SetDisplayDevice, 0x17 SetDigitalOutMode, 0x18 GetHDCPDownstreamState, 0x19 GetDigitalOutState, 0x1a printDisplayRegs, 0x1b GetGammaTable (0xc00 out), 0x1c GetDotPitch (DT `dot-pitch`), 0x1d GetDisplayArea, 0x1e Dithering, 0x1f SetUnderrunColor, 0x20 VideoPowerSavings. ## 4. GLES forwarding hook on 3.2

## 5. Minimal display model spec + milestones
Model (new `hw/arm/ipad1_display.c`, shaped like `ipod_touch_lcd.c` + `ipod_touch_mipi_dsi.c`):
- DISPLAY_PIPE0 0x89000000/0x7000: RAM-backed register file for 0x1000-0x6fff; special: 0x103c FIFO port (parse header/packets, apply reg writes at next vsync; bump completed-ID → 0x1048 low 16 bits; 0x1044 always 0; 0x101c return 0x20; 0x1050 write = no-op), 0x1028 enable / 0x102c W1C status (raise bit0 each frame, bit 0x100 too; IRQ 0x2a level = status&enable); scanout from 0x4044 (IOVA or PA) with 0x4048&~0x3f stride, 0x1030 size, format from 0x4040 bits 8-10 (0='ARGB'/BGRA 32bpp, 4='L565'), enabled iff 0x1038 bit8; optional UI1/video ignored; 0x2064 underrun color.
- CLCD 0x89200000/0x2000: 0x00 self-clearing 0x100 (soft reset), 0x50 bit0 ENVID, bit1 = !bit0 ("ready down"), everything else RAM (gamma/dither/timing). IRQ 0x29 never raised.
- MIPI-DSIM: reuse ipod model (STATUS polls: bit0, 0x100|lanes, 0x200|lanes<<4, 0x400, 0x100000; panel-ID reply; long-read type 0x1a). SWI: 0x14 bit0 self-set.
- DART2: either dead-simple (TLB_OP bit3=0, RAM regs) + DT without `iommu-parent`, or full STE/PTE walk (formats above). Scaler: reset bits self-clearing + nonzero version, or drop node (then CA's accelerator path is skipped; fallback untested).
- Vsync cadence: 60 Hz from the k48 timing (68.4 MHz dot clock, 1024+0x85+0x85+0x87 × 768+0xA+0xA+0xC ≈ 60 Hz).
Milestones: (1) iBoot logo: 0x5F700000 FB scanned via 0x4044 after openiBoot-like init (clcd.c:723-733); (2) kernel console FB: xnu writes boot_args video FB (same address), DisplayPipe adopts it and creates the transition mapping; (3) SpringBoard software-rendered: needs IOSurface (`PurpleGfxMem`), IOMFB swap FIFO, VBL IRQ 0x2a, packet-ID completion, either DART model or `iommu-parent` removal, panel-ID nonzero (or NVRAM `pinot-panel-id`), sgx node removed; (4) GLES forwarded: string patch `AppleMBXDevice`→existing class + mbxshim re-validated against 3.2's GLESCreateGC layout, or a new 19-entry gli shim with a 1652-slot dispatch.
